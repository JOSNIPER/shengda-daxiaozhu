## 为什么要在电脑上跑一个服务

手机浏览器有两条安全规则，直接把「手机网页去请求教务系统」这条路堵死了：

1. **同源策略**：网页只能请求和它自己同一个域名/端口的东西。
   教务系统是另一个域名，浏览器直接拦。
2. **混合内容**：网页如果是 https 打开的，就不许发 http 请求；
   而教务系统**只有 http，没有 https**（这条改不了，在学校那边）。

所以中间必须有个「翻译」：电脑上的 `bridge.py` 替手机去登录、抓数据，
再以**同一个源**的 JSON 接口交给手机页面。

```
手机浏览器  ──HTTP──►  电脑 bridge.py  ──HTTP──►  教务系统
  (页面)                (登录/抓取/转JSON)        (只有 http)
```

**凭据不出这台电脑**：学号密码只用 Windows 的 DPAPI 加密后存在本机，
不上传、不经过任何第三方服务器。整个程序没有一行统计/上报代码。

## 怎么跑起来

### 1. 装依赖

需要 Python 3.9 以上。`bridge.py` 除了标准库还要三个包 —— 注意 **`pycryptodome` 是必需的**：
`bridge.py` 一启动就 import `chaoxing.py`（学习通查课），那个文件用 Crypto 的 AES。
少装它会在启动瞬间 `ModuleNotFoundError: No module named 'Crypto'`，跟登录、网络都没关系。

```bash
pip install requests qrcode pycryptodome
```

校内/代理环境装不上 pip 源时，换国内镜像（实测阿里云可用）：
`pip install -i https://mirrors.aliyun.com/pypi/simple/ requests qrcode pycryptodome`

`qrcode` 只是为了在终端里打个二维码方便手机扫。不想装就加 `--no-qr`，
启动后手动把网址敲到手机上。

### 2. 启动

```bash
python bridge.py
```

屏幕上除了两个网址和二维码，还会打一段**配置说明**：现在挂的是哪一轨教务、
读的是哪份 config、哪些 `tableId` 还是 `TBD`（没抓包的功能会显示可操作的错误，不编数据）。

```
  电脑上打开：  http://127.0.0.1:8788/?k=xxxxxxxx
  手机上打开：  http://192.168.1.7:8788/?k=xxxxxxxx
```

- 在**电脑上**点第一个链接，可以先用鼠标把界面点一遍（界面是响应式的，
  电脑上看就是窄窄一条，跟手机一样）。
- **手机**用第二个链接，或者直接扫二维码。

端口被占了就换一个：`python bridge.py --port 8899`。

**两个启动参数（改造期用得上）**：

| 参数 | 干什么 |
| --- | --- |
| `--config PATH` | 换一份教务配置。默认读 `config/shengda.json`（`tableId` 全是 `TBD`，等业务接口报「还没配置」） |
| `--mock [PORT]` | **完全离线**跑通界面：连本机 `离线mock_ui跑通/mock_server.py`（默认端口 8090，账号 `2024010101` / `mock-pass`），不碰校园网、不需要真 tableId |

```bash
python ..\..\离线mock_ui跑通\mock_server.py 8090   # 先起 mock
python bridge.py --mock 8090                       # 再起桥，浏览器点界面
```

### 3. 手机连不上？按这个顺序查

**① 手机和电脑必须连同一个 Wi-Fi。** 手机用流量是打不开的。

**② 校园网 Wi-Fi 常常开了「客户端隔离」**（AP isolation）——
同一个 Wi-Fi 下的设备互相看不见，这是学校为了安全故意设的，
不是配置错了，也没法在电脑上改。判断方法：手机浏览器打开
`http://<电脑IP>:8788/api/health`，如果是「一直转圈 / 无法访问」，
而同 Wi-Fi 下电脑自己访问 `127.0.0.1:8788` 正常，那就是被隔离了。

绕开的办法，从省事到麻烦：

| 办法 | 怎么做 |
| --- | --- |
| **电脑开热点**（最省事） | Windows 设置 → 网络和 Internet → 移动热点 → 打开，手机连这个热点，然后用热点网段的那个 IP |
| 手机开热点给电脑 | 反过来连也行，注意电脑要连的是手机热点 |
| 家里/宿舍自己的路由器 | 直接连，通常不隔离 |
| USB 数据线 | 开 USB 网络共享，或用 `adb reverse tcp:8788 tcp:8788`（需要 adb） |

**③ Windows 防火墙。** 第一次会弹窗问「是否允许 Python 访问网络」，
要选**允许**并勾上「专用网络」。当时点了取消的话，
去「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」
把 Python 勾上；或者用管理员 PowerShell 加一条规则：

```powershell
New-NetFirewallRule -DisplayName "达小助" -Direction Inbound -LocalPort 8788 -Protocol TCP -Action Allow
```

> 那个 `?k=xxxxxxxx` 是一串随机口令，作用是**只让拿到链接的人能连**。
> 因为服务监听在局域网上，同一个 Wi-Fi 下别人也能访问到这个端口，
> 没有口令就等于谁都能用你的身份去查教务系统。
> 口令**只在第一次启动时生成**，之后一直复用（存在
> `%LOCALAPPDATA%\DaXiaoZhu\token.txt`），所以手机上的链接和
> 「添加到主屏幕」的图标重启电脑后照样能用。想换口令就删掉那个文件。

## 用起来

1. 打开就是**课表**（默认周视图）。
2. 底部「我的」→ 填学号密码 → **绑定并同步**。
   这里要的是**教务系统**（`jw.shengda.edu.cn:8090`，青果）的账号，
   登录经 CAS（`cas.shengda.edu.cn`）统一认证。
   ⚠️ 升达的课表/成绩 `tableId` 还没在校内抓包，同步回来的是原始行，
   课页面会显示「课表已同步 N 行，格子格式还没适配」而不是空页面。
3. 同步完自动跳回课表。**密码会加密存下来**，以后刷新、重开 App
   都自动同步，不用再输。只有真的登录不上时才让你重新输一次。之后：

> 换了手机、或者清了浏览器缓存？电脑上的凭据还在，所以空态页会多一个
> 「直接同步 · 学号打码」，点一下就行，不用再输密码。

> 🔴 已知缺口：如果校内实测 CAS 的 REST 登录**必须**带算术验证码，
> 这一版还登不上 —— `kingo.captcha()` 已经把验证码取回来了，但
> `/api/login` 没有把「答案 + uid」传进去的通路（界面上也没这个输入框）。
> 抓包确认要验证码的话，这是第一件要补的事。红线不变：**不自动识别验证码**。

| 想干什么 | 怎么做 |
| --- | --- |
| 翻周 | **左右滑动课表**（跟手，松手才翻）；或顶部 `‹` `›`；或点「第 N 周」直接跳到任意一周 |
| 回到本周 | 点「今天」 |
| 换成一天的列表 | 右上角图标切换周/日视图，日视图里同样能左右滑动翻天 |
| 改学期开始日期 / 总周数 | 我的 → 学期设置（或在选周弹层底部点「学期设置」） |
| 看某门课的教师/教室/周次 | 点那个色块 |

| 改每节课的上下课时间 | 我的 → 上课时间 |
| 看考试时间/地点/座位号 | 底部「考试」（顶部可切学期：大一上 / 大一下 / 大二上…） |
| 找一间空教室自习 | 底部「**空教室**」（选日期 + 节次，可选校区/教学楼/类型/座位数/教室名） |
| 看学校最近的通知 / 活动 / 停水停电 | 底部「**公告**」（不用登录；点一条能看时间和地点） |
| 重新同步 | 我的 → 同步教务处数据；**课表页右上角**、成绩页、考试页右上角那个圈也是 |
| 解绑 | 我的 → 解除绑定（会删掉电脑上存的密码和手机里的数据） |

同一天同一格撞了两门课（教务系统里真有这种情况）时，
两个课名都会写出来，中间用虚线分隔 —— 不会只显示一个然后藏起另一个。
撞课格**不写教室和老师**：一格两门课时分不清哪个属于哪门，写了反而误导
（详情面板里每门课各写各的）。课名各给 3 行。

**为什么要有「隐藏课程」**：教务系统里会有你实际上不上的课。实测 2026 秋季
就有一门「高等数学Ⅰ(二)」，四个时段**全部**和别的课撞车，而实际课表里没有它。
这种脏数据没法靠规则自动判（撞课也可能是真的调课），只能自己点一下藏起来。

🔴 **「隐藏这门课」藏的是整门课，不是这一节。** 判据是**课程代码**
（`course.code`，比如 `B1600100`）：点一次，这门课这个学期所有时段、
所有教室**一起消失**。同一个时间格里的**其他课不受影响**。
想只藏某一节目前做不到 —— 恢复在「我的 → 已隐藏的课程」，整门课一起回来。

右下角的小「单 / 双」角标表示这门课隔周上：**所有周次奇偶性一致**才标
（比如 `2,4,6,8,10,12,16,18` 是双周，中间第 14 周停课不影响），
奇偶混着就不标 —— 宁可漏标，不猜错。

### 顶栏那几个按钮

从左到右：`‹` 上一周 · 第几周（点它选周）· `›` 下一周 · 「今天」· 切视图 · **刷新**。

刷新是用户 2026-10-19 提的：

> 建议在课程表页面右上角也加上刷新功能

以前只有「我的 → 同步教务处数据」和成绩/考试页右上角能刷，课表是每天看得最多的
一页，想拉一次新课表得点进「我的」—— 多绕一层，而且没人会想到刷新藏在设置里。

几条实现上的取舍：

- **它刷的是整份同步**（课表 + 成绩 + 考试），不是只刷课表。分开做没有意义：
  一次登录就能全拿回来，分开反而是四次登录。
- **同步中图标转圈、颜色变强调色**，不换成文字「同步中…」—— 按钮只有 34px 宽，
  塞不下字，而且换字会让整条顶栏左右跳一下。
- 🔴 **四个入口共用一个单飞开关 `syncing`。** 连点三下只会发一次请求。
  不挡的话就是三次登录，而学校那边登录有 3 秒防抖，第二次开始大概率报
  「请不要过快点击」，看起来像密码错了。
- **没数据时整条顶栏收起**（`renderSchedule` 里 `weekbar.hidden = !hasData`）。
  一排点了没反应的按钮比没有按钮更让人以为界面坏了；那时候空态里有「去绑定」。
- 🔴 **320dp 上让「门数」先让位。** 加了刷新按钮之后，320dp 的顶栏只剩 107px，
  `10.19 – 10.25 · 14 门课` 放不下会被裁成 `10.19 – 10.25 · 14 …`。
  门数包在 `.wk-cnt` 里，`@media (max-width: 345px)` 时 `display: none` ——
  「这周是几号到几号」必须完整，「几门课」是锦上添花。

### 格子是怎么画的

两条规则，都是为了「一眼看出哪几个时段有课」：

**① 没课的地方就留空。**

空格子原来是 `background: var(--card)` 加一圈边框，结果整张表被切成 70 个
灰白小方块 —— 满屏都是「格子」，反而看不出哪些是真有课的。
现在空格子完全透明、不画边框，色块直接浮在背景上。
（`.g-cell { background: transparent; border-radius: 8px; }`）

**② 有课的格子尽量把「在哪、谁上」写全。**

一个色块里最多三行：课名 → 教室 → 老师。

| 元素 | 规则 |
| --- | --- |
| 课名 | **13px**，最多 2 行；跨 2~3 节放宽到 3 行，跨 4 节以上给 4 行 |
| 教室 | **10.5px**，一行放得下就写 `@01B 104`，放不下只在**空格处**折成两行；**两个教室就两行**（9.5px 起，放不下自动缩到 8px，见下） |
| 老师 | **10px**，多个老师只写第一个（`张强,苏博` 在小格子里只能显示成「张强,...」）。放不下自动缩到 8px，8px 还放不下就折成两行 |

几个刻意的取舍：

- **课名不许被压缩。** `.bn` 原来是 flex 子项，会被自动压短：明明给了 3 行额度，
  实际只画 2 行还带省略号（「企业管理与…」就是这么来的）。现在 `flex: 0 0 auto`。
- **课名折行尽量两头一样长。** `text-wrap: balance` —— 不写的话「线性代数」
  会断成「线性代 / 数」，看着像被切掉一截。
- **教室号不能 `break-all`。** 那是按字符断，`@01B 104` 会变成
  「@01B 10 / 4」，房间号断在中间比截断还糟。改成 `word-break: normal`，
  只在空格处折行。
- **单节的格子不写老师。** 56px 放不下「课名 2 行 + 教室 + 老师」，
  让老师让位，完整名单在点开的详情里。
- **教室号里的脏数据先清掉。** 教务系统里有
  `06B304(电工技术实验室)`、`02B506(D机房),02B505(C机房)` 这种写法。
  括号里是场地类型（找教室用不上），逗号是「一门课两个教室」。
  完整原文在点开色块的课程详情里。
- 🔴 **一门课两个教室，两个都画。** 用户 2026-10-19 拿「数据结构」举例：
  `02B506(D机房),02B505(C机房)` 两个都是上课地点，以前只显示第一个。
  现在按逗号拆开、**一间一行**（`02B506` / `02B505`）。
  两间时**去掉 `@` 前缀**（单间仍写 `@01B 104`）：那个符号纯占宽度，
  360dp 的格子只有 44px 宽，省下它才放得下；同时去掉楼栋和房间号之间那个空格，
  多一个空格就多一次折行，两行教室会把整格撑破（实测溢出 10px）。
  两行时锁死 `white-space: nowrap`，宁可字小也不能折行。
  括号里的「D机房 / C机房」不放格子（放不下），详情面板里是原文。
- 🔴 **老师名字量出来再压字号，不许写死。** 用户 2026-10-30 截图：周三那门
  「大学英语I（三）」老师显示成 **`李…`**，而周一同一门课 `李怡琼` 是完整的。
  差别不是高度（两块都是 2 节），是**宽度** —— 周三那门是单双周课，块上带一个
  「双」角标，`.g-block[data-par] .bt { padding-right: 12px }` 让老师那行
  让出 12px。CSS 里那句注释写着「留 12px 正好放下三个字」，但它是按 **9px**
  算的，而 `.bt` 实际是 **10px** —— 差 1px 就截。
  ⇒ 现在和教室号走同一个 `fitRoomLines`：量 `scrollWidth > clientWidth`，
  压字号到 8px 为止；8px 还放不下才加 `.wrap` 折到第二行（CSS 限高两行）。
  ⚠️ 这个 bug **在 390dp 的桌面 Chromium 上复现不出来**（42px 的字正好有
  44px 可用），只在 360dp / 320dp 才截 —— 所以判据
  `check_teacher_fit.py` 要把 320/360/375/390/412 五个宽度都过一遍。

### 正在上的那节课会亮起来

**周视图和日视图都有**，判据是同一个 `liveAt(tt, p, q, nowMin)`（2026-10-20 加）：

- **跨两节的大课算一整块**：从**头一节的开始**到**最后一节的结束**。
  只看第一节的结束时间，15:00 时那块会提前灭掉。
- **课间也算在上**（第 5 节 15:15 下课、第 6 节 15:25 上课，中间那 10 分钟灯不灭）——
  学生这会儿还在那间教室。
- **只在「本周 + 今天那一列」亮**。翻到第 5 周还亮一块，用户会以为第 5 周
  也有课正在上。`todayIdx` 在 `week !== weekOf(today)` 时直接是 -1。
- **时间没配就不亮**。`hhmmToMin('')` 返回 `null` 而不是 0 —— 往 0 兜底的话
  `nowMin >= 0` 恒成立，一节没配时间的课会永远显示成「正在上」。

样式上两个视图**故意不一样**：

| | 画法 | 为什么 |
| --- | --- | --- |
| 日视图 | `box-shadow: 0 0 0 2px`（外发光） | 卡片宽，外面有地方 |
| 周视图 | `inset 0 0 0 2px`（内描边） | 格子只有 44~50px 宽、gap 才 1px，往外画会压到隔壁那一列 |

⚠️ 深色模式里有 `.g-block { box-shadow: none }`，同特异性、后写胜 ——
必须再补一条 `.g-block.live`，否则**深色下根本不亮**（这条有测试钉着）。

### 日视图的左右留白是 14px，不是 7px

`.scroll.tight` 的 7px 是**给周视图 7 列挤空间**用的（每列多 2px，直接决定
课名少折一行）。日视图只有一列，没理由跟着挤 —— 但一开始复用了同一个类，
结果卡片圆角 12px、留白只有 7px，**圆角比留白还大**，看着就像被屏幕边缘切了一刀。
（2026-10-20 用户说「课程块右侧被白边挡住」，量下来其实没裁，是余量太窄。）

现在 `.dayview` 自己再加 7px，合计 14px；顶部那条「正在上」的 `margin`
从 14px 收到 7px，两处都落在 14px 上，左右对齐。

📌 这类问题有通用判据：**`border-radius` 大于等于左右留白，视觉上就会「顶到边」**。
`_lab/out/_dbg_edge.py` 会遍历每个页面的所有元素，把「圆角 ≥10px 且留白 <12px」
的挑出来（320 / 360 / 412 三种宽度各跑一遍）。目前 0 处。
- 🔴 **教室号靠 CSS 定死字号不可靠，得运行时量。** 用户 2026-10-19 第二次反馈：
  改成 9.5px 之后 `@02B506` 末尾那个 `6` 还是被裁掉一半。
  原因是 **Android WebView 的 Roboto 比桌面 Chromium 宽** —— 在桌面用 Playwright
  量着放得下，真机上就溢出，而且 `overflow` 不可见时表现成「字被切掉一截」。
  现在 `fitRoomLines()` 每次画完都量一遍：`scrollWidth > clientWidth + 0.5`
  就从 9.5px 每档减 0.5 一直试到 8px，谁宽缩谁、窄的保持 9.5。

  ⚠️ 两个坑：① 页面 `display:none` 时 `clientWidth === 0`，
  硬缩会把字号一路压到 8px，所以先 `if (!el.clientWidth) continue`，
  等 `switchTab('schedule')` 切回来再补量一次；② 缩字号前要先
  `el.style.fontSize = ''` 复位，不然上一次缩过的值会一直挂着。
- **撞课的格子不写教室和老师。** 一格两门课的时候分不清哪个属于哪门，
  写了反而误导。课名各给 3 行，其余信息点开看。
- **老师名右边留 11px 给「单/双」角标。** 原来是 13px，
  正好把「李怡琼」挤成「李…」。

列宽是怎么抠出来的（412dp 手机上每列约 52px）：

```
左右留白 7px × 2 + 节次栏 30px + 列间隙 1px × 8 = 52px 一列
```

留白从 14px 收到 7px、节次栏从 38px 收到 30px、间隙从 2px 收到 1px ——
每列比上一版多 4~5px，正好够把「@01B 104」放进一行。

### 左右滑动翻周

手指在课表上往左推，课表跟着往左走，松手才决定翻不翻 —— 这叫「跟手」。
只判「滑了多远」的话，手感像在戳按钮，不像在翻页。

**一屏同时画三页**（上一周 / 本周 / 下一周），并排塞进一条 `.track` 里。
这是「不白屏」的关键：只画当前这一页的话，手指一拖就把唯一那页推走了，
底下什么都没有，看到的就是「先整屏空白，再蹦出下一页」。

- 位移基准是**一页宽**：`translateX(-W + 拖动距离)`，松手后整页平移到 ±W。
- **左边节次栏固定不动**，放在轨道外面。放进轨道的话，滑到一半屏幕上会出现两条时间栏。
- 松手动画 240ms，动画结束后在**同一帧**里重画三页并把轨道摆回中间，
  看不到跳。
- 一页宽要用「子元素的 `getBoundingClientRect().width`」量，
  **不能用 `clientWidth`**：容器有纵向滚动条时它会窄十几像素，上一页会从左边缘漏出一条彩边。

三条硬规则（都是踩过才知道的）：

| 规则 | 为什么 |
| --- | --- |
| 先看前 8px 的方向，横向要压过纵向 1.4 倍才接管 | 课表纵向要滚 10 节课。不判方向的话，上下滚动会被抢成翻周 |
| 到头只给 28% 位移（橡皮筋） | 第 1 周再往右拉，得让人知道「没得翻了」，而不是硬顶或直接翻到第 0 周 |
| 松手后 350ms 内的 click 全部吞掉 | 否则滑动结束时手指底下的课程块会被点开，弹出详情，看着像误触 |

翻页有两种触发：划得够远（屏幕 22%，上限 70px），或者快速一甩（>0.45 px/ms）。

CSS 上必须给滚动容器 `touch-action: pan-y`：不写的话横向拖动会被浏览器
当成「横向滚动容器」，JS 收到的 `touchmove` 是零碎的，跟手就变成了「没反应」
或者「一下子跳过去」。

### 每一天都写着日期

日头是两行：**周一**（小、灰）在上，**10/12**（大、深）在下。

以前是「一 12」挤在一行，而且日期用的是 `<i>` 标签 —— 斜体、10px、灰色，
基本看不出那是日期。更糟的是单个「一」渲染出来就是一根横线，
摆在日期上面像条分隔符，不像星期，所以现在写「周一」。

「今天」那一列：表头垫一层浅蓝，整列再铺一条 5% 透明度的浅蓝「泳道」。
只高亮表头的话，翻到别的周再翻回来很容易看丢；铺一整列，扫一眼就知道哪列是今天。
5% 是上限 —— 再深就会把色块的颜色带偏，同一门课在别的列和这一列看着就不像同一个颜色了。

### 周末列：固定显示，不做「有课才出来」

**一周固定 7 列，周一到周日全显示**（2026-10-19 改的）。

上一版是「整个学期有周六/周日的课才把那列加进来」，理由是 7 列挤在 390px 上
每列只有 44px，一行放不下几个字。但用户当天就报了：
「为什么没有周日了？很多人周日也有课」。

这个规则有两个毛病，都是「省 7 像素」换不来的：

1. **看不见 = 不可信**。没课的那天整列消失，用户分不清是「真没课」还是「软件不支持周日」。
2. **列数随数据变**，两个人截同一周的图对不上，翻周时也容易看错列。

现在 7 列的实际宽度（`--days: 7`，留白 7×2、节次栏 30、间隙 1×6）：

| 屏宽 | 列宽 |
| --- | --- |
| 412dp | 51.7px |
| 390dp | 48.6px |
| 360dp | 44.3px |

`audit_density.py` 逐块量过：13px 课名在 360dp 上也不截断。
真挤的话该动的是字号和留白，不是把一整天藏起来。

⚠️ `visibleDays()` 返回的是**真实星期几**（0=周一），不是列号。
跳过某天的逻辑已经删了，但 `cols[ci]` 这种写法留着 —— 以后再加「只看工作日」
之类的开关，别拿 `ci` 当星期用。

### 登录状态和密码记忆

「我的」页有两种样子，区别只在**本机有没有存住凭据**：

| 情况 | 界面 |
| --- | --- |
| 没绑定过 | 显示学号 + 密码输入框，一个「绑定并同步」按钮 |
| 绑过、凭据还在 | 显示头像/姓名/班级，右上角有「立即同步」 |
| 绑过、但凭据没存住 | 上面那些照常显示，**再额外弹一张黄色卡**请你补一次密码 |

🔴 第三种情况是 2026-10-18 用户报的 bug：「我明明登录上了，还说没有绑定账号」。

根因是**两个判据不一致**：界面看「有没有课表数据」，
`/api/sync` 看「有没有存住密码」。数据在、密码没存 → 界面觉得绑定了，
同步却报「还没绑定」，而且绑定表单藏在「未绑定」那一支里，用户根本找不到入口。

现在的处理：

- 登录**一律** `remember: true`，不再跟勾选框走 ——
  原来那个「记住密码」勾选框是祸根，取消勾选就会出现这种半绑定状态。
  现在已经**删掉**那个勾选框，改成一句说明。
- 凭据状态做成三态 `BOUND`：`true` / `false` / `null`（还没问过）。
  `null` 不提示，否则页面刚打开会闪一下。
- 后端错误分两类：`EamsError.kind === "auth"`（学号密码不对）才请用户重输；
  网络问题、系统改版一律不弹密码框，免得白输一遍。

**2026-10-19 补的一刀**：用户又报「每次打开都要输密码，存到本地很难吗」。
查下来是两条独立的毛病，凑在一起就成了「永远记不住」：

1. `saveCred` 只返回 `false`，说不出**为什么**没存上 —— 界面上只有一句
   「密码没能加密保存」，看不出是 Keystore 坏了、还是文件写不进去。
2. **重新输密码那条路根本不看 `res.saved`**，存不进去照样弹「已保存，下次打开会自动同步」。
   所以用户以为记住了，下次打开又看到那张卡片 —— 这就是他说的「问题还没解决」。

现在的做法：

- `saveCred` 返回值从 boolean 改成 **String**：空串 = 存好了，`soft` = 走了备用方式，
  `fail: 原因` = 没存上。`app.js` 里 `credSaved()` 是唯一入口，**两条路都必须走它**。
- 没存住时 `BOUND` **不置 true**，补密码的卡片当场出现，并写明原因。
- `/api/state` 多返回一个 `credState`：`none`（从没存上）/ `ok` / `broken`（存着但解不开）。
  `broken` 是密钥被系统重置（换机恢复、升级）的情况，文案必须和「没存过」分开 ——
  把「解不开」说成「没保存」，用户会觉得这软件每次都在骗他。
- 兜底：Keystore 失败时用 `ANDROID_ID + 随机盐` 派生密钥再存一次（`s1:` 前缀）。
  弱一档，但比每次重输好，且仍然不是明文。

加密方式见下面「隐私」第 3 条。

### 第几周是怎么算的

课表里的「周次」是教务系统给的（每门课一个精确的周次列表），
但「今天是第几周」要靠**开学第一周的周一**推出来。

默认值：**2026-09-07**（2026-2027 学年第一学期）。这个日期是照实际课表核对的
——2026/10/18 是第 6 周周日，所以第 6 周周一是 10/12，往前推 35 天就是 9/7。

算法：秋季学期从 9/1 起、春季从 2/20 起，取**之后**最近的周一。
🔴 必须往「后」找：9/1 是周二，往前找会得到 8/31，整学期多算一周。

「我的」页会直接写出来：「按这个日期算，今天是第 N 周（共 24 周）」。
对不上就进「我的 → 学期设置」，把日期前后挪 7 天。

学期总周数（24）也不是猜的，取自课表页里的
`table0.marshalTable(from, startWeek, endWeek)` 第三个参数。

| 项 | 说明 |
| --- | --- |
| 学期（教务系统原文） | `2026-2027 学年第 1 学期` 这种编号，**是算开学日期的依据**，别改格式 |

不是存在课表数据里 —— 课表数据每次同步都会被整体覆盖，设置不能跟着被冲掉。

### 「大二上」是怎么算出来的

用户 2026-10-19 提的：**别再显示「2026-2027 学年第 1 学期」这种编号，
直接说大几。** 他说得对 —— 学生说自己从来不说学年编号，只说「我大二上」。

三个数就能定，全部来自教务处，不猜：

| 数 | 从哪来 |
| --- | --- |
| 入学年 | `profile.grade`（原文 `2025`）→ `enrolledAt` → 班级名 `25计科1班` → 学号前两位 |
| 学年起始年 | 学期名 `2026-2027` 的前四位；认不出来就按今天推（9 月开学算第一学期，1 月仍属上学年第一学期） |
| 第几学期 | 学期名里的「第 1 / 第一 / 第 2 / 第二 学期」 |

```
学期序号 = (学年起始年 − 入学年) × 2 + (第几学期 − 1)
大几     = 学期序号 ÷ 2 + 1      序号奇偶 → 上 / 下
```

实测：2026 − 2025 = 1 ⇒ 序号 2 ⇒ **大二上**，跟他自己的说法一致。

显示在四个地方：「我的」那行（`大二上 · 9.07 开学 · 24 周`）、
选周弹层副标题（`大二上 · 共 24 周`）、学期设置面板顶部（`现在是 大二上（按入学年 2025…）`）、
**成绩页的学期筛选条**（`全部 / 大一上 / 大一下`，以前写的是 `2025-2026 1`）。

🔴 **算不出来就返回空串，界面退回显示学期原文**：入学年推不出、
或者算出来的年级比学制还高（延期毕业 / 数据对不上）都不硬编 ——
宁可显示拗口的编号，也不能给一个「大七上」。

回归见 `_lab/out/check_grade.py`（19 项：跨学年、上下学期、四个来源、算不出来时的兜底）
和 `_lab/out/check_grade_chips.py`（11 项：成绩页 chip 文字、筛选结果、算不出时退回原文）。

## 考试页怎么选学期

用户 2026-10-19 提的：**考试时间这个界面也加上选学期的，选哪个学期就能看那个学期的考试安排。**

### 学期从哪来

教务系统有个学期下拉接口（`/eams/dataQuery.action?dataType=semester`），
一次给 **53 个学期**（从 2010 年到 2027 年都有）。全摆出来没法看，所以只留
「他读过 / 正在读」的：入学年之后、且不晚于当前学期。

```
入学年 2025，当前 2026-2027 第 1 学期
⇒ 留下 2025-2026-1、2025-2026-2、2026-2027-1
⇒ 显示成「大一上 / 大一下 / 大二上」
```

未来的学期一定没有考试，摆出来就是空按钮；入学前的学期不属于他。
**一个都筛不出来时返回空列表、不显示 chip**（界面退回只看当前学期）——
绝不硬编几个假学期糊上去，点进去是空的比没有按钮更让人困惑。

🔴 **必须先访问一次考试页，学期接口才有内容。** 2026-10-19 实测：新会话里直接
GET `dataQuery.action?dataType=semester` 回来是空的，先 GET
`/eams/stdExamTable.action` 之后同样的请求就有 53 项。代码里用
`_exam_page_seen` 记住这件事，已经摸过就不重复打一次。

### 怎么按学期查

```
GET /eams/stdExamTable.action?semester.id=257      ← 列表页切到那个学期
  → 页面里的批次下拉变成那个学期的批次
GET /eams/stdExamTable!examTable.action?examBatch.id=<批次>&semester.id=257
```

实测三个学期：257（2025-2026-1）5 个批次共 7 条、277（2025-2026-2）
5 个批次共 11 条、297（2026-2027-1）只有「平时结课考试」1 个批次 0 条。

两条链路各加了一个接口（契约完全一样）：

| 接口 | 干什么 |
| --- | --- |
| `POST /api/exams` `{semesterId}` | 取指定学期的考试。`semesterId` 不是纯数字直接回错，**不拿当前学期冒充** |
| `POST /api/semesters` | 列全部学期（界面自己筛） |

🔴 **切学期不重新登录**：登录本身要 3 秒（登录页要求「别点太快」），
每次都登就七八秒，手指点两下会以为卡死。所以复用上一次同步留下的会话；
会话真失效了才重登**一次**，重登还失败就如实报错，不循环打学校服务器。

### 绑定后会把「能同步的全同步」

用户 2026-10-19 提的：

> 首次绑定账号后直接把咱们软件能同步的东西全给同步了吧，比如考试信息，
> 不然看考试信息还得在对应页面上等半天。

整份同步（`/api/login` 和 `/api/sync` 都走同一条路）本来就已经带了：
学籍 → 课表 → 成绩 → **当前学期**的考试 → 学期列表。缺的是**其他学期**的考试 ——
以前要等用户点 chip 才现取，一次三四秒。

现在 `applyPayload()` 结束时会调一次 `prefetchExams()`，在后台把
「他在读的每一学期」的考试依次取一遍，写进 `DATA.examsBySem`（落盘）。
之后切学期是**瞬间**的，一个请求都不发。

几条硬规矩：

- 🔴 **串行，绝不并发。** 学校那边登录有 3 秒防抖，一次放四五个请求过去
  是拿自己的账号开玩笑。`prefetchExams()` 用 `await` 一个一个来。
- 🔴 **只补没缓存的。** `examsBySem` 是落盘的，所以只有第一次绑定会真跑；
  以后每次同步都会发现「都有了」直接跳过。想重来就「清除本机缓存」。
- 🔴 **失败不重试、也不吞。** 某一学期取失败就把原因记进 `EXAM_ERR`，
  用户切过去看到的是「大一上的考试没取到 + 学校原话 + 再试一次」。
  失败的那个**不写缓存**（下次同步会再试），成功的照常写。
- 🔴 **换账号 / 解绑会作废正在跑的那一轮。** 用一个轮次号 `prefetchTok`：
  每次开新一轮就 `++`，旧循环每走一步都比一次，不相等就自己退出。
  不这么做的话，上一个账号的考试会被写进下一个账号的缓存里。
- 🔴 **解绑时先停后台任务，再去打网络。** `cancelPrefetch()` 放在
  `await api('/api/unbind')` **之前** —— 一个来回几百毫秒，放在后面的话
  这期间还会再发一个学期的请求，等于「用户已经点了解绑，后台还在拿他的凭据
  打学校服务器」。
- 补取期间考试页顶部有一行淡字「正在提前取其他学期的考试 · 2/4」，
  补完自动消失。不写这一行的话，用户切学期时看到的那一下等待是没来由的。

⚠️ **正在跑的那个请求收不回来**（`fetch` 一旦发出就没法撤回）。
「取消」保证的是**之后不再有新的学期被发起**，不是「已经发出去的那个也作废」。

回归见 `_lab/out/check_refresh_prefetch.py`（49 项）。

### 缓存与失败

- 取成功的学期存进 `DATA.examsBySem`（落盘），切回来**不发请求**、瞬间显示；
  当前学期直接用同步下来的那份。
- 换账号（`studentId` 变了）会清掉上一个人的缓存。
- 🔴 **取失败不许画成「没有考试」**：记下原因，界面说「大一下的考试没取到 + 原话」，
  还给一个「再试一次」。失败只在内存里，下次进来重新试 ——
  一次网络抽风不该被钉死成「这学期没有考试」。
- 某一学期没排考时写「**大一上没有考试安排**」，点明是哪一学期 ——
  不然用户会以为整个软件都没有考试数据。
- chip 条放在空态**上面、并且不受空态影响**：某一学期没排考时列表是空的，
  chip 要是也跟着藏起来，人就再也切不回别的学期了。

### 「已结束」还是「待定」

列表顶上那条汇总（`共 11 场考试 · 已结束 · 都是过去的考试`）要判断这个学期
**过完没有**。用户 2026-10-19 的原话：

> 大一下都过去了怎么还是待定？不应该是已结束吗？

一开始的写法是「只要有一场考试没定日期就算待定」，结果整个大一下都变成「待定」——
因为里面有一场「认识实习」，学校在日期栏里写的是 **`时间未安排`**。

🔴 正确的判断分两层，顺序不能反：

```javascript
const isPastTerm = pick.y < curT.y || (pick.y === curT.y && pick.s < curT.s);
// 学期已经过完 → 一律「已结束」，不管里面有没有没定日期的
// 学期还没过完 且 有场次没定日期 → 「待定」
// 其余 → 「已结束」（都是过去的考试）
```

先看**学期本身**在不在当前学期之前（`pick` / `curT` 都来自 `termParts()`，
认 `2026-2027学年1学期` 和 `2026-2027 学年第 1 学期` 两种写法），
再看有没有没定日期的场次。反过来的话，一场没排时间的实习就能把整个学期说成「待定」。

🔴 **学校的「未安排」是明确表态，不是「待定」。** 教务系统对没排的场次直接写
`时间未安排` / `地点未安排` / `座位未安排`。这些值要当空处理（`blankField()`），
否则详情里会出现「地点 地点未安排」这种重复；但日期块照学校原话写「**未安排**」，
不写「待定」——「待定」是我们猜的，「未安排」是学校说的。
`.exdate.txt b` 字号压到 12px、`white-space: nowrap`，「未安排」三个字不折行。

回归见 `_lab/out/check_semester_terms.py`（24 项，Python 侧）、
`check_native_exams.py`（25 项，APK 侧 JS，含和 Python 的逐字段对照）、
`check_exam_terms_ui.py`（48 项，界面：筛选、切换、缓存、空态、失败、重试、
过去的学期写「已结束」、占位行不显示）。

## 空闲教室（空教室查询）

数据来自教务系统「空闲教室查询」：`/eams/classroom/apply/free.action`（表单）
和 `/eams/classroom/apply/free!search.action`（查）。**只读，不占教室、不提交任何申请。**

### 四个坑，全是实测出来的

1. **必须先摸一次 `stdDetail.action`**。`free.action` 是受限动作，服务端要求
   session 里有「project 上下文」（郑航 = 本科）。只访问 `homeExt` 不算；
   登录表单加 `project.id`、query 加 `?project.id=1`、cookie 写 `projectId=1`
   **全都不管用**，一律 500 `project not selected`。先 GET 一次 `stdDetail.action`
   就正常了。落成 `EamsClient._ensure_project()`，`_project_ready` 记状态。

2. **`pageSize` 必须传，而且能给到 1000**。默认只回 **20 行**，
   而且那 20 行是按容量升序的前 20 个 —— 全是常年空着的小实验室，
   换节次、换日期看起来「一模一样」，会让人以为筛选没生效。
   实测 `pageSize=1000` 一次回全 **756 行（755 间 + 1 行「停课」）**。
   以前默认 200，只能拿到最小的 200 间。

3. **第一行经常是「停课」**：没有教学楼、容量 0。那是学校塞在结果里的
   **状态行**，不是教室。不能画成教室（界面上会出现一间叫「停课」的教室），
   也不能一声不吭删掉 ⇒ 单独进 `notice`，界面说一句
   「学校在结果里标了『停课』，那不是教室，已经跳过」。

4. **会话被踢时学校回的是 HTTP 200 + 一句话**：
   `本次会话已经被过期（可能是由于重复登录）`（20 字节）。
   不认这一条，`parse_free_rooms` 就会得到 0 间，界面说「这一节没有空闲教室」——
   **把错误说成事实**。所以 `free_rooms()` 里加了一道：
   返回里没有 `gridtable` 就抛 `EamsError`，让 `_with_client` 重登一次再试。
   （正常的「查不到」返回里是有这张表的，只是 tbody 为空，不会误判。）

### 结果怎么排

学校是按容量**升序**给的，一屏下来全是 6 座的小实验室。界面按
**容量从大到小**排（sort 稳定，同容量保持学校原顺序），但两条要先挡掉：

- **「公用资源」一律排最后**。这一类根本不是教室：办公室、国际教学办、
  「请联系任课老师」「无卷开放考试」这种占位条目，容量写 900~9999。
  按容量排会把它们全顶到第一屏（真数据实测过）。
- **9999 是「不限额」的占位值**，当容量排序没意义 ⇒ 按 0 算，
  显示成「容量不限」（0 显示「容量未知」，两种不混）。

### 交互上的几条规矩

- **默认查「接下来那一大节」**（`defaultRoomBlock()`）。下午四点打开 App
  却默认查上午 1-2 节，等于每次都白查一次。晚自习都下课了默认查明天。
- **第一次进这一页自动查一次**（`ROOM.autoTried`），整个 App 只自动查这一次。
  切走再回来不重查 —— 空教室不会几秒钟就变，但每切一次就打一次学校服务器。
- **改条件停手 320ms 再查**（`roomChanged()`）：连点「今天→明天→后天」
  不该各打一次学校服务器。**查询期间又改条件只记一个「等会儿再查」**
  （`ROOM.again`），绝不并发；`ROOM.tok` 轮次号负责作废过期响应。
- **节次块按学校节数生成，不能写死**（`roomBlocks()`，2026-10-20 修）。
  块数 = `DATA.unitCount / 2`，`unitCount` 是 native.js 从课表 HTML 里
  `unitCount = 10` 正则读出来的，学校自己声明的节次数。
  郑航 10 节 → 5 块（1-2 … 9-10）；别的学校 12 节 → 6 块，自动多出 11-12。
  ⚠️ 以前硬编码 6 块（照「常见高校 12 节」抄的），郑航界面上凭空多一个
  「11-12」，用户直接问「不是一天只有 10 节课吗」。
- **节次用 3 列网格，不用横向滚动**：320dp 上一行放 6 个 chip 放不下，
  最后一个会被裁成「9-」，而 chip 上的横向滚动条是看不见的，
  用户只会以为「那节没有」。5 块时排成 2 行（3 + 2）。
- **筛选默认收起**（`ROOM.filterOpen`）。三个下拉天天摆在最上面只会把结果
  挤出屏幕。摘要那行写当前条件（`龙子湖校区 · 08楼 · ≥50 座`），收起也看得见。
- **筛选项取不到不影响查询**：把原因原话摆在筛选框里，加个「重试」，
  查询照常能用。别把整页弄成不可用，也别装作「本来就没有筛选项」。

### 失败与空态必须分开

- 查失败 ⇒ 错误卡片（服务端原话 + 再试一次），**不显示结果区**，
  更不显示「没有空闲教室」。
- 真·0 间 ⇒ 摘要写「没有空闲教室」，列表空着。
- 截断 ⇒ 「学校这次回了 N 行就停了，可能还有更多没列出来」。
  不写这句，「全校就这 200 间」会被当成事实。
- 解绑 / 清缓存 ⇒ `resetRooms()` 把结果和筛选项一起扔掉。
  留着别人的查询结果比留着别人的课表更糟 —— 那张表看起来完全是「现在的」。

回归：`_lab/out/check_rooms_free.py`（107 项，界面 + Python/JS 解析逐字段对照）。

### 入口为什么从「一个门图标」改成三个字

0.5.0 把空教室从底部 tab 收进课表页顶栏，给它的是一扇门的图标。
用户 2026-10-22 的反馈很直接：

> 空教室查询入口有点莫名其妙，就一个图标，用户很难知道那是干嘛的

他说得对。图标能表达「教室」，但表达不了「**找**空教室」—— 而后者才是这个功能的用途。
当时的取舍是顶栏太挤（7 个控件），放不下字。

现在的做法是**把字挤进去**，代价是顶栏其他元素各让一点：

| 改动 | 让出 |
|---|---|
| `.wk-btn` 宽 34 → 30 | 16px（4 个图标按钮） |
| `.weekbar` gap 2 → 1 | 6px |
| 「今天」内边距 12 → 9 | 6px |

腾出来的 28px 正好放「空教室」三个字（实测 71px，390dp 下标题还剩 132px）。

**同一次排查还发现两处同类问题：**

1. **视图切换**原来是个网格图标 —— 网格能表示「周视图」，但表示不了
   「点一下会换成另一种」。改成直接写当前视图的一个字（`周` / `日`），
   跟分段控件的习惯一致。
2. **校历**的入口更隐蔽：只有「点周次标题 → 弹层里再点『看校历』」这一条路，
   而标题上看不出能点。现在标题右边加了个 `▾`（「能展开」的通用符号），
   另外在「我的」里补了一条纯文字的「校历」。

「我的」里同时补了「找空教室」—— 有人就是习惯从设置里找东西，不该逼他记图标。

⚠️ **别把 `#wkTitle` 的 aria-label 写成「打开校历」**。它打开的是
「跳到第几周」弹层，校历是弹层里的一个按钮。`check_entries.py` 第 [3] 段
专门钉住这一点。

验收：`_lab/out/check_entries.py`（17 项）、`_lab/out/check_weekbar.py`（24 项，
在 320/360/390/412 四个宽度下量「日期有没有被省略号截断」）。

## 校园公告

底部中间那个「公告」tab。**这一页不需要登录** —— 它是整个 App 里唯一
没绑教务账号也能用的栏目。刚装完 App、还没来得及输密码的时候，
至少有个东西是能看的。

### 打开就有：本机缓存 + 后台刷新

0.7.0 起，公告列表存在本机（`localStorage` 的 `zt.notice`）。
顺序是**先画本机那份，再去后台刷**：

```
boot()  →  ntCacheLoad()  读本机 → 立刻有内容
        →  enterNotice()  超过 10 分钟才去刷（不 await）
```

以前是「第一次点进公告 tab 才抓」，而 6 个学校站点串起来要两三秒 ——
用户看到的是空白页转圈。现在打开就有，刷新是后台的事。

四条规矩：

1. **只存列表，不存正文。** 正文（`NT_DETAIL`）是几十 KB 的解析结果，
   而且列表最上面几条一进来就会重新补，存了也是白存。
2. **最多存 80 条**（`NT_CACHE_MAX`）。公告一直累积，不裁会把 localStorage 撑爆。
3. **刷失败不清缓存。** `ntCacheSave()` 只在成功时调用 ——
   用空列表盖掉上一次那份，就把「这次没刷上」变成了「什么都没有」。
4. **详情预取只在公告页显示时跑。** 以前 `renderNotice()` 无条件预取 8 条正文，
   开机后台刷新一次就会顺手敲 8 个详情页，而用户可能正在看课表。

界面上不额外标「这是缓存」—— 摘要行本来就写着「`10-22 09:15` 更新」，
时间戳自己会说清楚新旧。

验收：`_lab/out/check_cache.py` 第 [9] 段（重开 App 后列表**立刻**有内容）。

### 列表和详情为什么是两个接口

| 接口 | 干什么 | 一次要抓几个页面 |
|---|---|---|
| `/api/notice` | 标题 / 日期 / 来源 / 分类 | 6 个列表页 |
| `/api/notice/detail?u=` | 正文里的「时间 / 地点」+ 摘要 | 1 篇正文 |

合成一个接口的话，一进页面就得抓 60 篇正文 —— 慢，而且把学校服务器打疼。

但只有标题的话，这页跟直接看学校官网没区别。用户要的是
「什么时候、在哪儿、有没有餐券」，那三样只在正文里。
所以列表画完之后**异步**给最上面 8 条补详情，补到一条就更新一张卡：
用户不用等，也不会盯着一屏「正在加载」。

| **要办事** | 报名/缴费/申报/提交/补办/办理/确认/注册/选课/转专业/评教/医保 | 28 条 |

🔴 **宁可少标，也别乱标。** 标错分类比不分类更糟 —— 用户点进「影响出行」
发现是活动，下次就不信这个分类了。

分类 chip 上带条数（`影响出行 2` / `要办事 28`），用户一眼就知道
「今天没什么事」还是「有三件事要办」。这比写一段说明文字直接得多。

### 「时间 / 地点」是怎么抠出来的

正文里常见这几种写法，都要认：

```
活动时间：2026年10月21日（星期三） 7:00      ← 「标签：值」在单独一行
展览地点：龙子湖校区中心广场 展览时间：10月20日—10月25日   ← 两个标签挤在同一行
```

第二种是坑：只按「取下一行」会把整行同时当成时间和地点，
界面上就会出现时间、地点两行字**一模一样** —— 看着像程序坏了。
所以要先把同一行按「标签：值」拆开。

🔴 **「发布时间」不是「活动时间」。** 教务处的页面把这两件事写在同一行：

```
发布时间：2026-10-20文章来源：实践教学科
```

只按「标签里有『时间』两个字」去取，会把**发布日期**当成活动时间显示出来，
界面上一本正经地写「时间 2026-10-20」，实际那天只是文章发出来的日子。
**这比不显示更坏。**

抠不到就不显示那一行，**不写「无」** —— 「没读到」和「没有」是两件事。

### 已知缺口

## 校园（智慧门户）

底部第四格「校园」。这一页装的是**智慧门户**里的东西：一卡通余额、消费明细，
以及 19 个办事入口（请假、第二课堂、打印中心、心理测评、勤工助学……）。

这一页和前面几页有个根本区别：**它用的是另一个密码**。

### 门户和教务是两套密码，不是一套

学校那几套系统各管一摊，账号体系也是分开的：

| 系统 | 地址 | 用什么登录 | 航院通拿它做什么 |
|---|---|---|---|
| 教务系统 | `jwglxt.zua.edu.cn` | 学号 + 教务密码 | 课表 / 考试 / 成绩 / 空教室 |
| **智慧门户** | `rhmh.zua.edu.cn` | 学号 + **门户密码** + 算术验证码 | 一卡通 / 19 个办事入口 |
| 校园网认证 | `202.196.169.166` | 校园网账号 | 不碰（那是桌面端的事） |

所以「校园」页第一次进去要**单独连一次门户**，输的是门户密码，不是教务密码。
这不是重复输入，也不是 bug —— 学校本来就是两套。

⚠️ 门户**错 5 次就锁号**。这是这一页所有设计取舍的源头，下面会反复提到。

### 底部为什么从 6 个变回 5 个

原来底部挤了 6 格：课表 / 考试 / 公告 / 校历 / 空教室 / 我的。
用户的反馈很直接：「主流 App 底部最多 5 个」。那砍谁？

| 原来 | 现在 | 为什么 |
|---|---|---|
| 课表 | 课表 | 主功能 |
| 考试 | 考试 | 一学期看几次，但看的时候很急 |
| 公告 | 公告 | 不用登录也能看，唯一「刚装完就有东西看」的页 |
| 校历 | → **课表页点顶部周次** | 一个学期只变一次，不值得占一格 |
| 空教室 | → **课表页顶栏的「空教室」按钮** | 和课表是同一个时间维度 |
| 我的 | 我的 | 设置 |

收进去的两项本来就是「课表的另一面」：课表回答「今天上什么」，校历回答

### 「门票」和「身份证」

门户的登录状态分两层，这是整页最需要理解的一件事：

| | 是什么 | 存在哪 | 能活多久 | 过期了怎么办 |
|---|---|---|---|---|
| **门票** | `customsid` + `Authorization`（213 字符的 JWT） | `rhmh.zua.edu.cn` 域 | 几小时 | 拿身份证换一张，**不用密码** |
| **身份证** | `CASTGC`（CAS 的 TGT） | `sfrz.zua.edu.cn` 域 | 实测 **不到 7.2 小时** | 只能重新输密码 |

打个比方：门票是当天有效的游园票，身份证是本人证件。
票过期了拿身份证去窗口换一张就行；身份证也过期了，才需要重新登记。

换票只有两步：

```
POST https://sfrz.zua.edu.cn/lyuapServer/v1/tickets/{CASTGC}
     service=https://rhmh.zua.edu.cn/shiro-cas
  → 纯文本  ST-1234-abcdef...

GET  https://rhmh.zua.edu.cn/shiro-cas?ticket=ST-1234-abcdef...
  → 302 + Set-Cookie: Authorization=eyJhbGciOi...
```

🔴 **三条弯路都走过，记在这儿免得再走：**

1. `GET /lyuapServer/login?service=...` 带 `CASTGC` —— **服务器根本不看这个 cookie**，
   带不带都回 200 登录页。它只认自己的会话。
2. `GET rhmh.zua.edu.cn/auth` 带 `CASTGC` —— 同上。`/auth` 走的是 rhmh 自己的
   `customsid` 会话，会话一过期就跳去 CAS 登录页，看起来像「身份证也过期了」。
3. 回调地址拼成 `/shiro-cas/shiro-cas` —— **404**。`service` 有两个值：
   `/auth?service=` 要**裸域名**（它自己会拼 `/shiro-cas`），登录表单里的 `service`
   是**已经拼好的**完整地址、原样回传。混用就 404，而且不报错，只返回登录页。

### 密码为什么要在本地加密

门户在浏览器里就把密码 RSA 加密了才发出去。发明文服务器解不开，
表现是「密码错误」—— 极容易误判成用户记错了。

公钥是从门户 `app.js` 里抠出来的（1024 位，指数 65537）。但**加密方式不是标准的
PKCS#1 v1.5**：

```python
# 标准做法（❌ 会得到 PASSERROR）
block = b"\x00\x02" + random_bytes + b"\x00" + msg
c = pow(int.from_bytes(block, "big"), 65537, n)

# 门户实际用的（✅ 与浏览器密文逐字节一致）
m = int.from_bytes(msg, "little")        # ← 小端，末尾补 0，无随机填充
c = pow(m, 65537, n).to_bytes(128, "big").hex()
```

这是老版 jsbn 的写法：它把密码字节按**小端**当成一个大整数用。
靠「已知明文 + 已知密文」反推才确认 —— 大端三种分组长度全错，小端三种全对。

🔴 `PASSERROR` 这个错误码**分不清**「密文解不开」和「密码真的不对」。
所以排错时先确认加密对拍一致，再去怀疑密码。

### 一卡通

连上门户后第一张卡就是余额，点「消费明细」就地展开 —— 这里没有别的操作，
弹新层反而多一次「返回」。

接口是 **POST**（GET 会返回 `401 您正在尝试访问未授权的功能!`，
那个文案会把人往「重新登录」带偏）：

```
POST /api/upp/cardFrontlist/getCard/1b1029d961e94aa196fb7f0ec072d622
     {"startpage": 1, "enablePagging": true}
```

| 字段 | 含义 | 坑 |
|---|---|---|
| `RQ` | 消费时间 | — |
| `XFZD` | 消费地点 | 学校自己的命名 |
| `DBXF` | 单笔金额 | **本身带负号**，别再减一次 |
| `ZCLX` | 类型 | — |
| `YE` | 余额 | **前面有空格**，要 `strip()` |
| `pageTotalCount` | 总条数 | 实测 33 条 |

一页固定 12 条（服务端写死），33 条要翻 3 页。上限 4 页：再往前翻对
「最近花哪了」没意义，而每页都是一次请求。某一页失败就**停在已经拿到的地方**，
不整块报错 —— 少给几笔比什么都看不到强。

支出**不标红**。中国用户看到红字第一反应是「涨了/出事了」，而这里是花出去的钱。

### 消费小结：一句话要说清「这份数据覆盖到哪儿」（0.9.0）

明细上面那条小结算三件事：本月合计、笔数、日均；再加「常去」「最大一笔」。

难点不在加法，在**分母**。门户那个接口一页 12 条、最多翻 3 页 ⇒ 手里只有
最近 33 笔。这个月要是刷了 50 次，我们只看到 33 条。所以：

| 情况 | 判断 | 界面上怎么说 |
|---|---|---|
| 数据里最早一笔**早于本月 1 日** | 本月从月初就有记录，统计完整 | 「本月 3 笔 · 日均 ¥1.84」 |
| 最早一笔**就在本月内** | 不知道月初到那天之间有没有刷过 | 「10-05 起 3 笔」+「门户只给最近 33 笔，10-05 之前的没算进来」 |

🔴 **截断时不给日均。** 连「这几天花了多少」都不知道，除出来的数只会误导人。

三条实现上的规矩：

1. **只算支出。** 充值、补助是正数，混进「花了多少」里就全错了
   （测试里专门放了一笔 +100 做反向对照：算进去会得到 59.50，正确是 40.50）。
2. **「常去」要 ≥ 2 次才算。** 只去过一次说「常去」等于没说。
3. **明细是全量、小结是本月**，两者条数不一样是正常的 —— 小结里写清「本月」，
   不让人去对账对不上。

### 余额提醒：常驻一条，不弹窗（0.9.0）

低于阈值时，「校园」页的余额下面出现一条淡黄底的行内提示。默认 20 元，可改可关
（「我的 → 余额提醒」）。

- **不弹窗**：弹窗会被顺手点掉，而「快没钱了」这件事需要在你想起来的时候还看得见。
- **不标红**：这是提醒，不是错误。红色会让人以为卡出问题了。
- 🔴 **余额没读到时什么都不说**（`bal == null`）。「没读到」不等于「没钱了」，
  说成 0.00 元比不说糟得多。
- 阈值填了看不懂的值就明说「填 1 到 999 之间的数」，不悄悄当成 20。

验收 `_lab/out/check_ykt_stats.py`，27 项。其中 [1] 和 [2] 是一对反向对照：
同一份消费数据，只改「最早一笔的日期」，界面就必须换一套说法 ——
只验一边的话，一个「永远写本月」的实现也能通过。

### 过期之后为什么只要算一道验证码（0.8.0）

用户问的原话是：「为什么不能把账号密码都存到本地，登录过期后只需要输入验证码就行了？」

**答案：能，而且早就该这么做。** 之前没做不是技术上做不到，是保守 —— 这条限制是「没做」，
不是「做不了」。

先把三件事分清楚，它们经常被混成一件事：

| 东西 | 是什么 | 能活多久 | 能不能续 |
|---|---|---|---|
| `CASTGC` | **身份证**（CAS 的 TGT，`sfrz` 域） | 实测 **< 7.2 小时** | ❌ 过期不续 |
| `customsid` + `Authorization` | **门票**（`rhmh` 域，JWT） | 几小时 | ✅ 身份证还活着就能换 |
| 密码 + 算术验证码 | 重新办身份证的手续 | — | — |

所以「过期」只有两种结局，没有第三种：

1. **身份证还活着** ⇒ 自动换门票，用户完全无感（`pfRenew()` 在做这件事）。
2. **身份证死了** ⇒ 只能重新办一张，也就是重新过一遍「密码 + 验证码」。
   这一步**没法自动化**，因为验证码是给**人**出的（门户错 5 次锁号，
   所以绝不能写个识别器去猜 —— 猜错一次就是一次错误计数）。

既然第 2 步省不掉，能省的只剩「翻密码本」这一步。于是：

- 登录成功时把 `(学号, 密码)` 加密存本机 ——
  APK 走 `CredStore`（Android Keystore，和教务那份同一套机制），
  网页版走 DPAPI 的 `portal.bin`。
- 过期后弹层里密码那一行变成「**已保存 · 点这里改成手动输入**」，
  人只需要填一道算术题。

四条必须守住的规矩：

1. **密码永不回显。** `/api/portal/status` 只回 `saved`（存没存）和 `savedUser`
   （存的是哪个学号），**不回密码本身**。前端也就没有「显示密码」这个能力 ——
   没有这个能力，就没有「不小心把它画到界面上」这种事。
2. **密码框留空 = 用存着的那份。** 由后端 / 原生层自己取用，前端只发 `{user, code}`。
   这样密码连一次都不用在 JS 里过一遍。
3. **学号对不上就拒绝，一次都不试。** 存的是 A 的密码、这次填的是 B 的学号 ⇒
   直接报错让人手输。拿 A 的密码去撞 B 的账号 = 帮用户把号锁了。
4. **只有「门户说密码错」才删本机那份，验证码错不删。**
   `PASSERROR` / `NOUSER` / `USERLOCK` ⇒ 删掉（留着只会拿错密码反复撞）；
   `CODEFALSE`（验证码算错）⇒ **留着**（手滑一次就把密码删了，用户下次还得重输，
   等于白存）。这两种情况方向相反，所以 `portal.py` 的 `PortalError` 多带了一个
   `code` 字段 —— 拿中文文案去 `in` 判断是不行的，改一句话就崩，而且不报错。

还有一点：**「断开门户」和「解除绑定」会把密码一起删。** 只清会话不清密码的话，
换个人用这台手机点「连接门户」就直接进去了。

代价说清楚：手机丢了 / 被拿走，学校门户账号就是敞开的（含那 19 个办事系统）。
不过教务密码本来就已经这么存了，增量只有门户这一套 —— 而且照样要过验证码那关。
不能接受的话点「断开门户」，密码立刻删掉。

验收脚本 `_lab/out/check_portal_cred.py`，35 项。其中 [6] 和 [7] 是一对反向对照：
同一个「登录失败」，`PASSERROR` 必须删密码、`CODEFALSE` 必须留着 ——
只验一边的话，一个「任何失败都删」的实现也能通过。

### 为什么进这一页不联网了（本地缓存）

0.7.0 起，**进「校园」页一个门户请求都不打**。数据从本机读。

原因很实际：身份证（CASTGC）撑不过 7.2 小时，一天要撞好几次「门票过期」。
以前每次进页面都硬取一次，于是**每次都要输密码 + 算验证码** ——
可用户要看的往往只是「我上周五在食堂花了多少」，这个数几小时前的和现在的一模一样。

所以按「会不会变」把数据分成两类：

| 数据 | 会变吗 | 怎么处理 |
|---|---|---|
| 消费记录 | 只增不改，几小时前的完全够用 | **存本机**，进页面直接读 |
| 19 个办事入口 | 学校加应用才会变 | **存本机** |
| **余额** | 随时会变 | 存本机，但**必须标明是什么时候的** |

余额的处理是关键：它不能「不显示」，也不能「假装是最新的」。所以界面写
「余额更新于 3 小时前，点右上角刷新」，想看最新的才真去联网。

#### 顺带解决了「门户过期就什么都看不到」

以前门户一过期，整块内容就被换成「连接门户」，用户看到的是「数据没了」——
其实只是门票过期。现在：

- **过期 + 有缓存** → 数据照常显示，上面加一条「门户登录过期了，下面是 X 前的数据」
- **过期 + 没缓存** → 才显示「重新连接」

这条和上一节是同一个问题的两面：**缓存让过期从灾难变成提示**。

#### 三条必须守住的规矩

1. **同一个学号才认缓存。** 缓存里存了 `user`，跟当前学号对不上就整份丢掉重取。
   不校验的话，换人登录会先闪一下上一个人的消费记录。
2. **「断开门户」要连缓存一起清**（`store.del(KEY.card)` / `KEY.apps`）。
   理由同上。
3. **重新登录后必须强制联网**（`loadCampus(true)`）。
   走缓存优先的话，刚登完屏幕上还是上一次那个余额，等于白登。
4. **「清缓存」和「解绑」是两个层次，但共用同一个清理函数**（`clearLocalCaches()`）。
   以前这两处各抄了一份删除语句，0.7.0 加了三个缓存键之后就抄漏了 ——
   点「清除本机缓存」只清课表成绩，一卡通和公告还是旧的那份，**而且不报错**。
   现在：清缓存 = 只扔「能重新拉回来」的，**保留登录状态**（清个缓存不该逼人重输密码）；
   解绑 = 在清缓存的基础上再清登录状态（教务 + 门户两套）。
   注意清完缓存不能立刻联网重取 —— 那等于把刚删的又写回去。
   取数留到**用户下次真的进校园页**时（`renderCampus` 里判 `CUR_PAGE === 'campus'`），
   否则「清除」就成了摆设。

🔴 缓存在前端（`app.js` 的 `store` → localStorage），**不在 `bridge.py` / `native.js`**。
因为两个后端各写一遍必然对不上（红线：两套实现必须拿同一份输入对拍），
而这一层本来就跟「数据从哪来」无关。

验收脚本 `_lab/out/check_cache.py`，35 项（网页版）+ `check_cache_native.py`，17 项（APK 形态）。
每条断言都配了反向对照 ——
比如「有缓存时不发请求」必须和「没缓存时会发请求」一起验，
否则一个**永远不发请求**的实现也能让前半条通过。

### 19 个办事入口：点一下直接进

`GET /api/upp/appStore/queryApp?pageNum=1&pageSize=-1&excludeMobile=1`
返回 19 个，名字在 `labelName[0].zh_CN.labelName` 里（三层嵌套，
写成 `labelName[0].labelName` 会拿到 `undefined`）。

这 19 个系统**全部走 CAS 统一登录**，大半在 `xssq.zua.edu.cn`。
也就是说：只要门户登录着，这些系统本来就该免登录 —— 前提是**把登录状态带过去**。

0.5.0 之前是交给系统浏览器打开。浏览器有它自己的 cookie 罐子，门户的 `CASTGC`
不在里面，所以每次都要重新登录。0.6.0 改成在 App 内开一个 WebView
（`WebActivity`），先把 cookie 倒进去再开网页。

#### 难点：Android 里有三个 cookie 罐子

| 罐子 | 谁在用 | 里面有什么 |
|---|---|---|
| `java.net.CookieManager` | App 自己发的 HTTP（HttpURLConnection） | 教务的会话、门户的门票 + **身份证** |
| `android.webkit.CookieManager` | App 内所有 WebView | 以前是空的 |
| 系统浏览器的那个 | Chrome / 夸克 / 小米浏览器… | 跟我们无关 |

三个罐子互相看不见。免登录要做的就一件事：**把第一个罐子倒进第二个**。

`WebActivity.injectCookies()` 负责倒；「一条 cookie 该写成哪一行」在
`CookieJar.java` 里 —— 抽出来是因为它不碰任何 `android.*`，
可以在电脑上拿桌面 JVM 真跑测试（`_lab/portal/check_cookiejar.py`）。

#### 🔴 这里有个坑，第一版就写错了

看着最自然的写法是这样（遍历罐子里的每个地址，取出该地址的 cookie）：

```java
for (URI u : store.getURIs())
    for (HttpCookie c : store.get(u))  ...
```

跑测试才发现 **CASTGC 一条都取不到**。原因叠了两层：

1. `getURIs()` 返回的地址被 JDK **规范化成 `http://host`**，哪怕你当初是用 https 存的。
2. `get(uri)` 会按 scheme 过滤：**Secure 的 cookie 用 http 地址去取，直接不返回。**

CASTGC 恰好是 Secure 的。也就是说真机上「身份证」永远搬不过去，
网页照样弹登录页，**不报错、不崩、控制台干净** —— 这种 bug 光靠「点得动」发现不了。

改用 `getCookies()`（不做任何过滤）取全量，再用 `getURIs()` 的 host
反查「没有 Domain 的 cookie 属于谁」。

#### 另外两条规矩

- **Domain 原样保留。** `.zua.edu.cn` 这种跨子域 cookie 丢了 Domain 就退化成
  「仅此域名」，换个二级域名就看不见了，免登录直接废。
- **一律用 https 地址写。** WebKit 只对 Secure 的 cookie 挑 scheme，非 Secure 的
  写 https 也不会漏发；反过来 Secure 的用 http 写会被**直接拒收**。统一 https 最省事。

#### 「断开门户」必须连 WebView 的罐子一起清

WebView 的罐子会落盘（同一个 App 下次启动还在）。只清第一个罐子的话，
界面显示「没连门户」，点办事入口却还是登录态。`clearCookiesFor()` 里两处都清了。

⚠️ WebKit 没有「按域名删」的接口，只能整个清。这里可以接受：
主界面跑在 `app.local`，不用 cookie，那个罐子里只有学校站点的东西。

#### 界面文案是两套

APK 说「点一下直接进」，网页版说「点一下用浏览器打开，第一次进去要再登一次」。
网页版**不能**说免登录 —— 浏览器是第三个罐子，说了就是骗人。
实现是 `data-app` 属性 + `applyEnvTexts()`，和「同一份界面，两套说法」那一节同一个机制。

账号管理说明（三句 → 「密码只存在这台手机里。」）、周次提示（去掉「按这个日期算」
和「把日期前后挪 7 天」）。

#### ② 「结课判断」为什么一个学期都没判出来

旧判据是「这门课四个请求全成功、三个列表全空」连续 3 次、跨 7 天。
看着很规范，实测 37 门课里**22 门整个学期都判不出结课**。

原因很土：**历史学期的课不空**。上学期的作业还挂在课程下面，
永远不会「三个列表全空」，所以那套「攒次数」的逻辑对它们一次都没生效过。

换一个证据就行 —— 不看「有没有东西」，看**最新那条东西有多旧**：

- **空 = 没有证据**（老师可能还没发作业）⇒ 必须攒 3 次 + 跨 7 天，不敢快。
- **冷 = 有证据**（东西都在，只是最新一条已是 90 天前）⇒ **一次就能降频**。

`COLD_DAY = 90 天`。这个数的意思是「跨过一个假期还多」。区别不是谨慎程度，
而是**证据强度不一样**：空是「我不知道」，冷是「我知道，而且它很旧」。

### 0.37.0：更新下载「卡住」的真因不是慢，是拿不到文件大小

用户反馈「点下载后进度一直卡住，非常频繁，非常严重」，并猜是主站慢。

**实测两条线的差别（2026-11-01）**

| | CNB（国内，默认） | 主站（Cloudflare） |
| --- | --- | --- |
| 速度 | 1.27 MB/s，559 KB 用 0.44 秒 | 时快时慢，本机偶发 502 / 连接超时 10 秒 |
| 文件大小 | **不给**（`Transfer-Encoding: chunked`，无 `Content-Length`） | 给（`Content-Length` + `CF-Cache-Status: HIT`） |
| 断点续传 | 不支持（`Range` 回 200 整包） | 不支持（同样回 200） |

🔴 真因：CNB 不给总大小 ⇒ `DownloadManager` 的 `COLUMN_TOTAL_SIZE_BYTES`
读回来是 **-1** ⇒ `updDl.total` 为 0 ⇒ `pct` 恒为 0 ⇒ 进度条停在原地，
而旧看门狗要干等 30 秒才判死。**「下得快」和「看起来在动」是两件事。**

三处一起修：

- **进度条不确定态**：没有总大小时让条来回跑（`.updprog.indet`，带
  `prefers-reduced-motion` 降级），文字写「已下载 XX KB（这条线路没给文件大小）」，
  **不写假百分比**。
- **看门狗拆两段**：`UPD_BOOT_MS=8000`（一个字节都没下来 = 这条线没起来，直接换）
  / `UPD_STALL_MS=20000`（出过字节后再停 = 真断了，先等一等）。最坏等待 60 → 28 秒。
  ⚠️ 判据是 `updDl.got` 是否为 0，不是时间长短 —— 两段该做的事不一样。
- **可手动换线并记住**：`UPD_LINES` 从字符串数组改成 `{id,name,of}`，
  弹层里写「线路：国内线路 · 下不动就换一条」，换前必须 `u.cancel(updDl.id)`，
  换完写 `CFG.updLine` 重下。

**校园事务 7 张卡合成 4 张**：饮水（余额 + 三个周期 + 消费记录）/ 我的饮水机 /

点一下必须**不弹框**、必须**当场发请求**、而且**只发一次**；
按返回键关掉免责声明 ⇒ 一条启动请求都不许发（关掉 ≠ 同意）。

**二、这一页压紧了。** 问题不在「内容太多」，而在**每样东西占的地方太大**：

| 改动 | 原来 | 现在 |
|---|---|---|
| 余额卡 | 标题 / 大字 / 一条横线 / 三列 / 一行入口，250px | 大字和三列**并排**，142px |
| 设备行 | 名字 … 编号 `[接水]` 挤一行，71px | 名字 + 编号竖排、右侧胶囊按钮，53px |

🔴 不许靠「删功能」变短 —— 删掉的东西用户下次就找不到了；也不许把可点区域
压到 44 以下（`接水` 仍然是 44，它没被「紧凑」吃掉）。

这类问题**没有一条功能判据会红**：东西都在、都能点，只是每个都占太大地方。
所以 `check_water_ui.py` 新增了 **[U] 密度与排版** 一组，量几何：整页高度上限、

变异体也换成反方向的了（`_mutate_water2.py`）：把二次确认**加回来**、
给「结束」加确认、把两张单行卡**拆回去**、把接水按钮压到 30px —— 四个都必须变红。

### 0.31.0：扫机器上的码，而不是抄它的字

设备列表只返回**这个账号绑过的**机器，教学楼的机器经常不在里面。0.29.0 的
办法是「系统相机扫一下 → 复制文字 → 粘进来」，四步。现在点「添加设备」
直接开相机，对着码停半秒就好。

三件容易做歪的事，`check_scan.py` 一条一条钉住：

- **关掉要放掉相机**。只把浮层藏起来的话轨道还在跑，指示灯常亮，下次再开
  还会报「被占用」（`NotReadableError`）。三条关闭路径（×、返回键、切后台）
  各有一条断言，量的是 `track.readyState === 'ended'`，不是「浮层看不见了」。
- **权限被拒要说清是权限**。「相机打不开」这句话把「去设置里打开权限」和
  「这台机器没有相机」混成了一件，补救办法完全不同。
- **扫到别的码不能收**。归一之后还要看一眼形状（含 `/`、含空白、超过 64 位
  一律不收，其余放行）。不收这些的话，扫一张官网二维码就把整条 URL 存成
  设备号，接水时才报错 —— 用户会以为是我们的问题。

相机权限要原生那边批：`MainActivity` 不设 `WebChromeClient` 时 WebView
**直接拒绝**网页的 `getUserMedia`，网页只看到 `NotAllowedError`，表现是
「点扫码永远是黑的」且不报错。所以清单里加了 `CAMERA`（`required="false"`，
没相机的设备照样能装），`MainActivity` 里加了 `onPermissionRequest` →
系统权限弹窗 → `onRequestPermissionsResult` 这条链。

解码用 jsQR 1.4.0（Apache-2.0，`web/jsqr.js` 原样使用，许可证全文在
`web/jsqr-LICENSE.txt`）。

顺带两处改名／改版式：

- 「校园钱包余额」→「饮水余额」。它就是一卡通之外那个饮水机钱包，
  叫「校园钱包」会让人以为里面是校园卡的钱。
- 消费记录默认收起。这一页先回答「还有多少钱、今天花了多少」，明细是偶尔
  翻一次的。收起时右边写着最近一条（`¥0.16 · 3 小时前`），不展开也知道
  刚扣了多少。

### 0.30.0：三格下面那个「5.7 L」是估的

账单里**没有**出水毫升数。原版 `WaterConsumptionParser.kt` 的注释自己写着
「服务端当前没有返回可靠的出水毫升数字」，所以原版也是按「多少钱 ≈ 多少水」
换算的，这边照做。

既然是估的，三件事必须成立，判据都钉住了：

- **比例一直露在外面**。统计下面一行「按 ¥0.16 = 500 ml 估算」，点开能改
  金额和水量。不写这一行，用户会当它是量出来的。
- **金额是下限时，水量也是下限**。「≥ ¥3.20」配「1.0 L」就是两件事 ——
  一个说「至少花了这么多」，一个说「就是这个水量」。
- **关掉以后入口还得在**。行文案变成「水量估算已关闭」，点开按钮变
  「显示水量」。把入口一起藏掉的话，关了就没有任何办法开回来（红线 50 同族）。

取整照原版 `WaterEstimate.waterText()`：满 1000 ml 说「x.x L」，
否则四舍五入到 10 ml。🔴 判断在**舍入之前** —— 996 ml 会被舍成「1000 ml」
而不是「1.0 L」。这是原版的行为，不是笔误，`check_water_usage.py` 把它钉住，
免得以后有人「顺手修一下」就变成了「和原版不一样」。

配置存 `localStorage['wt.usage.local']`，坏数据（`amt = 0`、`"abc"`、负数）
一律退回默认 —— `amt = 0` 会让水量变成 `Infinity`，界面上就是「Infinity L」，
而且**不报错**。

### 0.29.0：教学楼的机器不在列表里怎么办

「我的设备」来自 `/ui/app/master`，只返回**这个账号绑过的**机器。
教学楼的机器往往不在里面，而它就在你面前 —— 这时候要能把它加进来。

做法是**粘贴二维码内容**，不扫相机。理由：
WebView 里读相机要额外的二维码解码库 **和** CAMERA 权限，那会在第一次接水时
弹一个「允许使用相机」；为了一件偶尔才做的事付这个代价不值。
系统相机本来就会读二维码，复制过来是同一个结果。
（顺带一提：`MainActivity` 没设 `WebChromeClient`，`<input type=file>`
点了**毫无反应且不报错**，所以「拍张照片再解码」那条路本来也是堵死的。）

`wtNormDevice()` 是照原版 `DeviceIdParser.normalize()` **逐条**抄的
（`_lab/out/_l798b/…/DeviceIdParser.kt`）。两处最容易抄歪的地方：

- `removeSurrounding` 是**先后两步**（先 `"` 再 `'`），不是「哪对在就剥哪对」；
- `removePrefix("did:")` 再 `removePrefix("DID:")` 只认这两种大小写，
  写成 `^did:` 正则大小写不敏感就多剥了一种。

照抄的东西改一边不改另一边**两边都不报错**，只是扫同一个码出来两个号。
所以 `_lab/out/check_device_id.py` 把原版 `DeviceIdParserTest.kt` 那 9 条
**原样**搬来当验收表（期望值是原版写的，不是我编的），另加 8 条按源码手推的边界。

- 本机记录存 `localStorage['wt.devs.local']`，只留最近 20 个（这是快捷入口，不是通讯录）；
- 列表 = 服务端 + 本机，按 id 去重，**服务端优先**（名字更准）；
- 只有手动添加的行才有「移除」，删前 `askConfirm`；服务端绑的那几台不给删 ——
  删了下次刷新又回来，按了没用比没有更糟。

### 公告：靠红点，不靠「记得点」

公告是低频页（一学期几十条，真正影响你的只有几条），但它是**不能错过**的那种低频。
所以底部那个 tab 保留，只是加了红点：**有新内容才亮**。

「看过了」记的是**最新那条的身份**（`url`），不是时间 —— 学校各站点的日期格式
不统一，拿时间比大小迟早比错；比身份只要回答「是不是同一条」。
🔴 这个判断**只读本机缓存**，不调 `ntCacheLoad()`：那个函数会把 `NT.tried`
置 true，于是 `enterNotice` 里「先画本机那份」那一支被跳过，用户点进去就是
空白等 6 个站点 —— 正是以前修过的毛病。
🔴 记「看过」的时机有两个：`renderNotice()` **和** `enterNotice()`。
只在 `renderNotice` 里记的话，第二次进来（`NT.tried` 已是 true）它不会再跑，
红点就再也不灭。

### 三条硬规矩

1. 🔴 **验证码绝不自动识别。** 门户错 5 次锁号，一次自动识别错了就可能把号锁掉。
   图交给人看、人算。登录失败后**立刻换一张** —— 验证码是一次性的，
   不换再点必然还是错。
2. 🔴 **只读。** 一卡通和办事入口只做读取，不提交任何申请、不代替用户操作。
   页面底部那句「只做读取，不会提交任何申请」就是这个意思。
3. 🔴 **判据是「需要登录的接口返回 200」。** 不是「cookie 里有 `customsid`」、
   不是「URL 里有 `ticket=`」、不是「跳到了某个页面」—— 这三种在假登录时**都会成立**。
   `/api/upp/Unauthorize/*` 这类白名单接口**不登录也返回 200**，拿它验证等于没验证。

### 直饮水：余额 / 设备 / 接水 / 积分任务（0.23.0 起步，0.24.0 补全）

直饮水走的是**慧生活798**（长沙云多啦），跟学校门户、一卡通都不通 ——
这是**三个**系统：门户管余额和办事，一卡通管食堂刷卡，饮水机自己一套。

0.22.0 先只做了一行跳转；0.23.0 起点进去是我们自己的页面（`#page-water`），
做三件事：**查余额 / 看绑了哪几台饮水机 / 一键接水**。
0.24.0 又补上四块：**停止接水 / 积分 / 消费记录 / 积分任务（点了才批量跑）**，
外加首次进入时的一层免责声明。
0.25.0 补的是**统计和结算**（见下面「今日/本月/本年」和「刚才那次」），
顺手修了一个 0.23.0 就带着的洞：**APK 上登录成功后 token 存不进本机**。
0.26.0 修的是**积分和任务列表都读不到** —— 两个都是「键名/层级猜错」，
见下面「0.26.0：两处读错，都是拿真源码才看出来的」。
🔴 它和「郑航百科」一样**留在 `#cpOff` / `#cpOn` 外面** —— 接水不需要门户，
门户登录过期了它也必须在。

**为什么不能把他的 App 内嵌进来**：安卓没有「一个 APK 跑另一个 APK 的界面」。
他的客户端是 Kotlin + Compose 原生 App，我们是「网页 + 安卓壳」，两套东西拼不到
一起 —— 要么把他的源码当 library 编进来（那就得整个换成原生），要么用插件化 /
双开框架（hook 系统、破坏签名，国内商店直接禁）。**能复用的只有接口协议**，
所以照协议自己写了一份。

**做哪些、不做哪些**（2026-10-30 用户定，别再往回加）：

| 功能 | 做不做 |
|---|---|
| 余额 / 设备 / 接水 / 停止 | ✅ |
| 积分余额 / 消费记录 | ✅ 只读 |
| 积分任务列表 / 每日签到状态 | ✅ 只读（0.26.0 起） |
| 执行任务 / 签到 | ✅ **0.26.2 起能跑**（签名自己算，见下面「签名」） |
| 后台自动签到 | ❌ 不做，替代方案也不做 |
| 充值 / 下单 | ❌ 不做，连套餐列表都不展示 |

两条「不做」的理由不一样：

· **后台自动签到**是账号行为，替他做而他又不在场，出了事他连什么时候发生的
  都不知道。**手动签到**（他点了才签）0.26.2 做了 —— 那是他在场的行为。
· **充值下单**涉及真钱，我们是 WebView 壳、没有支付宝 SDK，也没有商户资质和
  售后能力 —— 金额错了、退款、纠纷都落在用户身上。

🔴 **执行任务和签到有真实的账号风险**，这不是免责套话，是原项目 README 自己写的：
「平台可能限制账号、扣除 / 清零 / 冻结积分，任务也可能失败或无法获得奖励；
请求成功不等于奖励到账。**目前积分冻结、任务提示成功但未到账等问题仍未解决，
原因尚未确认。**」所以：第一次进积分任务页要读并确认风险（`TaskRiskConsent`）、
每次提交之间至少隔 30 秒（原版 `TokenTaskRateLimiter` 就是 30 秒）、
失败**不重试**、跑完**重新读一次积分**核验。

**登录不需要签名，但执行任务一定需要**（2026-10-30 分两次确认）：
`/acc/login` 带 `sign` 和不带、带一个假 `sign`，返回**一模一样**
（都是 `{"code":-1,"msg":"短信验证码错误"}`）⇒ 登录这条路服务端没有先校验签名。
但 `IlifeApi.postScore` 里**两条路都先算签名再发**，没有「不带 sign 也能过」
的分支。两件事别混。

⚠️ 一个**不报错**的坑：`targetSdk` 是 33，Android 11 起查别的 App 装没装
要先在 `<queries>` 里点名。不点名的表现是 `getLaunchIntentForPackage`
永远返回 null ⇒「明明装了，App 却说没装」，不抛异常、不进 catch，
只有真机点一下才看得出来。包名写在**三个地方**（`AndroidManifest` 的
`<queries>`、`NativeBridge.ALLOWED_APPS`、`app.js` 的 `WATER_APPS`），
少改一处就是「点了没反应」。

**界面上三条硬规矩**（改这一页之前先读）：

1. **`start` 是唯一有副作用的调用**（真的出水、真的扣钱）⇒ 必须二次确认，
   而且确认文案要把「会出水、会扣钱」写清楚 ——「确定吗？」等于没问。
2. **余额 `null` ≠ `0`**：接口改字段名和「真的没钱了」看起来一模一样，
   但该做的事相反 ⇒ `null` 显示「没读到」，绝不兜底成 `¥0.00`。
   设备列表同理：「一台都没有」和「没读到」要分开说。
3. **错误按 `kind` 说话**：`auth` 引导重登、`sign` 说「先看看手机时间」、
   `limit` 说等几分钟、`net` 说换网。一律「操作失败」等于什么都没说。
   `/dev/start` 的业务 code 逐条翻成人话（欠费 / 没签代扣 / 签约过期 /
   没绑一卡通 / 没设备控制权限 / 设备准备中 / 需要支付）。
4. **批量提交之间至少隔 30 秒，而且要能停**（0.26.2）。原版
   `TokenTaskRateLimiter.MINIMUM_INTERVAL_MILLIS = 30_000` —— 打太快会被限流，
   更糟是触发风控（限号 / 冻结积分，不是「重试一下就好」）。等待期间显示
   倒计时，并且随时可以点「停下」：让用户干等 30 秒看着屏幕不动，他会以为卡死。

🔴 **登录失败绝不自动重试**（验证码尤其）。错一次就换一张图，让用户重新读。
自动重试会把账号试锁。图形验证码**交给人读**，绝不自动识别 —— 和门户那道一样。

#### 签名是怎么算出来的（0.26.2）—— 以及 0.26.0 那条结论错在哪

完成一个任务 = `POST /acc/score/score-send?sign=<sign>`，body `{adId, type:101}`
（App 那一路还要 `&s=1` 和 `addScore` + `addScoreType`：`1705776998` 是 2、其余是 4）。
签名是 `md5(adId + 30 秒时间桶 + token 尾 8 + uid 尾 8 + salt)`。

0.26.0 我写过一整节论证「盐值拿不到 ⇒ 只能看不能跑」。**那个结论是错的**，
而且错在一个很具体的地方：我把「开源仓库里是占位实现」当成了「世界上没有真盐」。

- 开源仓库 `Signer.java` 是占位实现（salt 为空）—— 这是**真的**；
- 真值走 `secrets.properties` → `BuildConfig`，README 也明写不提交 —— 这也是**真的**；
- 但 **官方 Release 的 APK 是 CI 用真盐构建的，公开可下**。`BuildConfig` 里的
  `static final String` 会被 R8 **内联成字面量**留在 dex 里。

也就是说：我论证的是「源码里没有」，却把它当成了「取不到」。
教训记在这儿：**说「拿不到」之前先问「我到底试了几种办法」。**

取法（2026-10-30 做的，可复现）：

    dexdump -d classes.dex > dump.txt          # 112 MB，2.8 秒
    # 然后按**方法块**分组（`#<idx> : (in Lxxx;) name`），找两个锚点字符串：
    #   "authCode="                    → 登录签名，命中 Lca3;.E
    #   "score-send?sign="             → 内联的 postScore，两条路都在里面

为什么不能直接字节扫：R8 把类名/方法名全改了（字符串池里搜 `Signer` /
`IlifeApi` / `BuildConfig` **全 0 命中**），所以只能按**字符串锚点 + 调用点
上下文**找；而纯字节扫 `const-string` 会产生 2276 条噪音（没做指令对齐，
把字符串里的 `0x1a` 也当成了指令）。

两条路的盐不一样（`Signer.signApp` / `signMini` 除了盐完全一样）：

    App 路（1,1，VersionCode 3.1.9）：AbCdEfGhIjKlMnOpQrStUvWxYz12345，URL 末尾 &s=1
    积分路（1,5，VersionCode 2.0.178）：K9xP2QnR5T8wY3fA7cE1gJ4mL6oU0sZ

**把它们写进仓库合不合适？** 合适。这两个不是服务端密钥，是**客户端常量** ——
它们已经编译进每一个装了官方 App 的手机里，谁都能读出来。这和「别人的服务端
密钥」是两件事。（登录 body 里的 `cid` 同理。）

⚠️ 三个不报错的坑：

1. **`VersionCode` 头是必带的**。原版每个请求都带，服务端按它决定返回哪套结构。
   漏了不报错，只会拿到「另一个版本」的响应 —— 那种错最难查。
2. **时间桶用本机时间**。手机时间不准 ⇒ 签名错 ⇒ 服务端只说「签名错误」。
   所以界面上报签名错时，第一句是「看看手机时间准不准」。
3. **JS 的 MD5 必须按 UTF-8 字节算**。用 `charCodeAt` 直接拼的话，有一个非
   ASCII 字符两边就分叉 —— 表现是网页版能跑、APK 报「签名不对」，看着像服务端问题。

#### 两套账号：设备登录（1,1）和积分登录（1,5）

原版 App 里就是**两个账号**，不是一套 token 的两种用法：

| | ApplicationType | VersionCode | 登录 body | 管什么 |
|---|---|---|---|---|
| 设备登录 | `1,1` | `3.1.9` | `{authCode, un}` | 接水、余额、设备列表 |
| 积分登录 | `1,5` | `2.0.83` | `{authCode, un, openCode:'', cid}` | 积分、任务、签到 |

`Account.java` 里 `token`（积分）和 `appToken`（设备）并存，两个 token
**互不通用**。所以界面上的「账号」卡是**两行**：哪一行没登，就点哪一行的按钮。

🔴 **任务列表按平台各返回一份，必须合并去重**（原版 `TaskMissionPlanner.merge`
按 `refId` 去重，积分平台在前）。只登一个账号 ⇒ **少一半任务，而且看不出来少了**
—— 它只会显得「任务就是这些」。所以 `missions_all()` 返回的 `lanes` 三态
（`ok` / `missing` 没登 / `error` 读失败）必须一路转发到界面：`missing` 要引导
去登另一个账号，`error` 才是「接口出问题了」。这两件事混成一句「失败了」，
用户就会去刷新而不是去登账号。

⚠️ 一个**很隐蔽**的坑（0.26.2 修）：路由的登录守卫原来统一按
`state === 'ok'` 判。两套账号并存以后，只登一个时 `state` 是 `'partial'`
⇒ 明明能做的事全被挡住，还报「还没登录」，而用户刚登过。
现在按**这个操作实际需要哪个账号**分别判（`wGate('device')` / `wGate('any')`）。

⚠️ 同一族的第二处（自查发现的）：`/api/water/mission` 的 `platform === 'score'`
分支原来把 `use_app` **写死成 `False`**。可 `water_score_lane()` 的规矩是
「优先积分账号，没登就退回设备账号，**`use_app` 跟着变**」—— 写死以后就变成
「拿设备 token 配积分盐、发 `1,5` 的头」，服务端按无效 token 拒掉，
界面上看起来像「这个任务做不了」。签到那条（`/api/water/signin`）一直是跟着
回退走的，**同一个回退在两条路上效果不同，这本身就是错**。现在两边都取
`lane.use_app` / `lane.useApp`，并加了一条判据（只有设备账号时，
`platform='score'` 的任务必须按 `1,1` + `V_DEVICE` + `&s=1` 发出去）。

#### 0.26.0：两处读错，都是拿真源码才看出来的

用户 2026-10-30 13:13 的截图：积分两格都是「没读到」，任务列表报

lotteryEnable, missions`）」。**报错行为是对的**（没假装空），但**键明明在，
是我找错了名字**。

查了原项目 `life-798 5.5.0` 的源码（`_lab/out/_l798b/`，和 APK 同版本）才发现：

**① `acc-score` 的响应没有 `accScoreRsp` 那一层。**
原版 `IlifeApi.taskDataWithToken` 干的事是：

```java
missions.getJSONObject("data").put("accScoreRsp", score.getJSONObject("data"));
```

也就是说 `acc-score` 的 `data` **本身就是**「积分那一坨」，客户端把它塞进
`mission-lst` 的 `data.accScoreRsp` 里。我按 `data.accScoreRsp.validScore` 读，
所以在真机上永远读不到。
⇒ `_score_rsp()` 两种形状都认：套着就剥一层，没套就用 `data` 本身。

**② 任务的编号在响应里叫 `refId`，请求 body 里才叫 `adId`。**
原项目单测 fixture：

```json
"missions": [{"refId":"1705776998","name":"video","score":30,"limit":5}],
"accScoreRsp": {"validScore":…, "totalScore":…,
                "limits": [{"refId":"1705776998","limit":1}]}
```

`missions[].limit` 是**总次数**，`accScoreRsp.limits[].limit` 是**已做次数**
（`-1` = 不限次）—— 同名反义。原版 `TaskMissionPlanner.buildWork`：

```kotlin
val remaining = (mission.limit - (doneCount[mission.refId] ?: 0)).coerceAtLeast(0)
```

⇒ 界面上「还剩几次」是**我们自己减出来的**，响应里没有现成的剩余。
`used == -1` 时显示「不限次」，不显示「剩 -1 次」。

**③ 签到在 `data.dailyRSP`**：`{adId, score, config:[{rule:位掩码, score, msg}]}`，
本周已签的位掩码在 `data.accScoreRsp.daily.week`（bit0=周一 … bit6=周日）。
⇒ 0.26.0 加了一张只读的「每日签到」卡：今天签没签 + 一周七格。
⚠️ 星期几只能用**本机日期**（服务端没给）。时区不一致会错一天，那种情况下
宁可显示错，也不替用户补签。

**这一版的教训（比 bug 本身重要）**：

> 0.25.0 的判据 fixture 是按**我以为的形状**写的（`data.accScoreRsp.validScore`），
> 所以解析代码和 fixture 一起错，判据全绿 —— 和「假桥自证」是同一类错误：
> **测试桩按实现写，就永远测不出实现的错**。

#### 今日 / 本月 / 本年，和「刚才那次」（0.25.0）

原版 WaterWidget 的主屏是「余额 + 今日/本月/本年消费」，接水结束还会通知

1. **统计只能按「已经读到的账单」算**。账单是分页的，没读完时那个数是**下限**
   ⇒ 写成 `≥ ¥3.20`，不写成 `¥3.20`。把下限说成总额，和「没读到说成 0」
   是同一类错（红线 58）。有一条金额读不到（`money === null`）时同样降级成下限
   —— 宁可给下限，也不许把「这条不知道多少钱」当成 0 悄悄跳过。
   判断「这一期读完了没有」靠的是**最老那条的时间**：它早于这一期的起点，
   才能说这一期是完整的。
2. **不编「约 x 升」**。金额↔升数要一个兑换比例（原版可配置），真值我们不知道，
   所以「刚才那次」只报金额。账单几分钟后才出账 ⇒ 读不到就写「账单还没出」，
   **绝不显示 ¥0.00**（那是「免费」的意思）。
   标题也写「账单合计」而不是「消费」：服务端账单里有没有充值记录我们不知道
   （`type` 的取值没见过，按红线 58 不许兜底猜），叫「消费」就得保证只算消费。

## 学习通作业（0.10.0 起；手机版 0.11.0 起）

「我的 → 学习通」能看你有哪些作业还没交、各还剩多久。

### 只做「读」，不碰别的

这个项目对学习通只做一件事：**把你自己的作业列表读出来**。

不做签到、不做刷课、不做自动答题、不代交作业。原因不是「技术上做不到」，而是：

- 那些是学术诚信红线，代刷代签在很多学校是能记进档案的；
- 超星有分级风控：**首次警告 → 冻结 24 小时 → 灰名单要人工申诉**。
  它判的是「行为像不像脚本」，不是「你读还是写」。所以连只读都要克制。

同理，登录失败一次就停，**绝不自动重试**。重试会把 `needVcode` 撞成 1，
之后就得人做滑块验证，越弄越糟。

### 为什么要 40 秒

学习通**没有**「一次拿全部作业」的接口。作业挂在每门课下面，只能一门一门来：

```
课程列表（1 个请求，一次拿全 37 条）
  └─ 每门课 2 个请求：
       ① 进课程页 → 拿 stuenc（302 后 URL 里）+ workEnc（HTML 里）
       ② 带着这两个去要作业列表
```

实测 32 门课（同一 courseId 只查一次）≈ 64 个请求 ≈ **43 秒**。

所以界面是「点一次 → 后台跑 → 结果存本机 → 写明更新于几分钟前」，
不是实时。每次进页面都跑这个，手机受不了，超星也受不了。

### 两个 enc 必须配对（这个坑很深）

`stuenc` 和 `workEnc` 是两回事：

| | 在哪 | 变不变 |
|---|---|---|
| `stuenc` | 302 之后 URL 的 `?enc=` | **每次进课程页都变** |
| `workEnc` | HTML 里 `<input id="workEnc">` | 课程级固定 |

两个必须来自**同一次**课程页加载。混用旧的新的，服务端就回一句「无权限的操作」，
而且 HTTP 状态码还是 200 —— 很容易误判成「这门课没作业」。

顺带记一笔：2026-10-22 在这个坑里耗了三轮，最后一轮的原因特别蠢 ——
打印 URL 时按 190 字符截断了，`enc` 少了最后一位。

### cookie 分两个域，混在一起就「无效的用户」

```
passport2.chaoxing.com : JSESSIONID、route        ← 只属于登录站
.chaoxing.com          : UID、_uid、_d、vc3、uf、cx_p_token、…
```

把前两个也发给 `mooc1.chaoxing.com`，服务端会拿着不属于它的 session 去查用户，
直接回「无效的用户！」。所以必须用 requests 的 cookie jar 按域自动匹配，
**不能用 Cookie 头硬塞**。

### 状态不止四种

实测遇到 6 种：

| 状态 | 算哪边 |
|---|---|
| 未交、未开始 | **待办** |
| 已完成、待批阅、已批阅 | 已交 |
| 已互评 | 哪边都不算，单独提一句 |

「已互评」既不像「还没做」也不像「做完了」，所以不当成任何一边 ——
宁可少提醒一条，也不要让你以为它已经处理完了。

另外：**「没有倒计时」不等于「已过期」**。实测真的有「未交但没写截止时间」的作业
（大学英语I(三) 就有 7 条）。所以没有倒计时的条目只是不标红，不会被隐藏。

### 有课查不到时会说出来

某门课拿不到 `workEnc`（比如马克思主义基本原理）、或者中途登录态失效，
这些课会记进 `failed`，界面上写「有 N 门课没查到」，
**不会**让它悄悄变成「这门课没作业」。

### 手机版也接了（0.11.0）

0.10.0 时 APK 端 `/api/cx/*` 是直接回「手机版还没接上」的。0.11.0 把它接上了，
但**实现方式和电脑版不同**，这点值得记一笔：

| | 电脑版（网页 / 桌面） | 手机版（APK） |
|---|---|---|
| 谁跑逻辑 | `chaoxing.py`（Python） | `web/native.js`（JS，在 WebView 里） |
| 谁发请求 | `requests.Session` | `Android.req2` → `HttpURLConnection` |
| cookie 罐子 | requests 的 jar | `java.net.CookieManager`（全局，`ACCEPT_ALL`） |
| 存 cookie | DPAPI → `chaoxing.bin` | `CredStore` → Android Keystore |
| AES 加密密码 | PyCryptodome | `CxNet.aesB64`（JCE） |

Java 层只做了三件非它不可的事，其余全在 JS：

1. `CxNet.aesB64` —— AES 加密密码。放 JS 也能做，但 `crypto.subtle` 要求安全上下文，
   哪天页面加载方式一变就静默不可用；JCE 没这个前提。
2. `CxNet.dumpCookies` / `loadCookies` —— `java.net` 的罐子只有 Java 能摸到。
   **不导出的话 App 一退出罐子就空了**，每次开 App 都要重新登录。
3. `CxNet.hasLogin` —— 判断罐子里有没有 `UID`（`.chaoxing.com` 域上跨站有效的那份）。

为什么解析放 JS 不放 Java：WebView 有 `DOMParser`，按属性取节点比在 Java 里
手写 HTML 解析稳得多，而且**解析逻辑只有一份**（`_lab/cx/check_cx_js.py`
拿同一份真实 HTML 对拍两边的结果，逐字段比）。

cookie 分域的问题靠 `CookieManager` 天然解决：它自己按 domain 匹配，
不会把 `passport2.chaoxing.com` 的 `JSESSIONID` 发给 `mooc1.chaoxing.com` ——
那正是电脑版踩过的「无效的用户！」那个坑。

**存的是 cookie，不是密码。** 学习通登录一次能管很久，存 cookie 就够了；
少存一份密码，就少一次「拿旧密码反复去撞」触发风控的机会。

**失败不重试。** 和电脑版同一条规矩：重试会把 `needVcode` 撞成 1，
之后每次登录都要人做滑块；再撞下去是冻结 24 小时。



**默认就开着，默认「每天一次」查一次**，不用去设置里找。一次请求几百字节，
不下载任何东西；查到新版本才弹窗。

为什么不是「每次打开」：一天开十次 App 就查十次，而一天之内根本不会有新版本，
纯属白耗流量。想更勤（或者干脆关掉）在设置里改。

「我的 → 检查更新」里能改：一个开关 + 三档频率（每次打开 / 每天一次 / 每周一次）。

### 清单长什么样

`version.json`（跟发布页同一个域名，`https://hobson2233.dpdns.org/hangyuantong/version.json`）：

```json
{
  "name": "航院通",
  "version": "0.1.1",
  "code": 2,
  "size": 235339,
  "sha256": "…",
  "apk": "https://…/hangyuantong/dl/hangyuantong-0.1.1.apk",
  "apk_cn": "https://maven.cnb.cool/…/hangyuantong/0.1.1/%E8%88%AA%E9%99%A2%E9%80%9A.apk",
  "page": "https://…/hangyuantong/",
  "notes": ["一句话一条更新内容"]
}
```

- **`code` 是整数，比版本号字符串优先**。`"0.10" < "0.9"` 是字符串比较的经典坑，
  而且版本号迟早会写成 `0.1.0-beta`。没有 `code` 的老格式才退回比版本号。
- `size` / `sha256` / 下载地址由 `build_apk.py` 写，`notes` 从 `RELEASE-NOTES.md` 抄。
- **`apk` 和 `apk_cn` 是同一个包的两条线路**（sha256 一样）：
  `apk` 走 Cloudflare（发布站），`apk_cn` 走腾讯云 CNB。
  点「立即更新」时**优先用 `apk_cn`** —— Cloudflare 在国内下得慢；
  清单里没有 `apk_cn`（老格式 / 这版还没传 CNB）就退回 `apk`，不猜。

### 应用内下载（0.1.2 起）

点「立即更新」不再跳浏览器，而是：

```
DownloadManager 入队 → 轮询进度（600ms）→ 下完算 sha256 → 对得上才拉起安装器
```

- 文件落在 `getExternalFilesDir()`（应用私有目录）：**不需要存储权限**，
  卸载时一起清掉，不会在相册/下载目录里留垃圾。
- **两条线路依次试**：先 `apk_cn`（CNB），失败才换 `apk`（Cloudflare）。
  和主程序「只在失败时换源」是同一条规矩。
- **sha256 对不上就删掉，绝不装**。清单里说 A、下回来是 B，中间被人换了 ——
  这时候「帮你装上」是最坏的选择。界面会给一个「用浏览器下载」的退路。
  ⚠️「算出来不一样」和「读不到文件」是两件事，提示语要分开写。
- **关掉弹层不等于停止下载**：点「后台下载」只收起界面，下载在系统里继续跑，
  通知栏有进度。重开弹层会接着显示（`updDlId` 存在设置里）。
- 缺「安装未知应用」授权时，按钮变「去允许安装」，跳系统设置页，
  回来再点「安装」—— 不去硬撞安装器。

### 几个必须记住的坑

1. **清单必须带 `Access-Control-Allow-Origin: *`**。
   APK 的页面源是 `https://app.local`，网页版是 `http://127.0.0.1:8788`，
   两边都是跨域。少了这个头，`fetch` 会静默失败 ——
   表现成「永远显示已是最新版本」，又是一个把错误说成事实的坑。
2. **查更新失败要彻底安静**（自动检查时）。查更新失败不代表任何功能坏了，
   弹个错误框只会让人以为软件出问题了。手动点的时候才把原因写在面板里。
3. **「以后再说」只跳过这一个版本**。存 `updSkip = 版本号`，
   下次发新版照弹；手动点「检查更新」也照弹 —— 那是他自己要看的。
4. **自动检查不许抢用户正在用的弹层**。查到新版本时如果用户正开着「学期设置」，
   直接把内容换掉会让他填了一半的日期凭空消失。所以先记在 `updPending` 里，
   等弹层关掉（`MutationObserver` 盯 `hidden` 属性）再补上。
5. **结果不要用 toast 报**。弹层从底部升起，toast 也在底部，正好压在按钮上。
   结果写在弹层自己那一行字里，或者直接换成「发现新版本」。
6. **下载走系统 `DownloadManager`，浏览器只作退路**（0.1.2 起）。
   WebView 默认没有 `DownloadListener`，点 `.apk` 链接**什么都不会发生** ——
   所以早期是直接把地址交给系统浏览器。现在改成应用内下载：
   `DownloadManager` 入队 → 轮询进度 → 校验 sha256 → 拉起安装器。
   浏览器那条路还留着，给三种情况兜底：网页版（没有原生桥）、
   校验失败、以及用户自己点「用浏览器下载」。
   ⚠️ `getUriForDownloadedFile()` 返回的 `content://` **自带读权限**，
   不需要 `FileProvider`（我们也引不进来 —— 没有 androidx），
   这是手工打包能用这条路的关键。
   ⚠️ **做不到静默安装**：Android 不许 App 自己装自己，最后一定弹系统安装器。
7. **两条线路必须是同一个包**。`apk`（Cloudflare）和 `apk_cn`（腾讯云 CNB）
   指向同一个 APK，sha256 必须一样 —— 用户从哪条线下到的都得是同一个东西。
   所以 `apk_cn` 里的版本号由 `build_apk.py` 从 `VERSION_NAME` 拼，
   不能手写；传 CNB 用的是**同一个 dist 文件**，不要另打一份。
   ⚠️ `apk_cn` 指向的地址要求**这版已经传到 CNB 了**（见下面「发版顺序」），
   先出包后传的话，中间那段时间点「立即更新」会 404 —— 所以传完再发站。
8. **WebView 里没有 `WebChromeClient` 就没有 `confirm()`**（0.1.3 起）。
   `MainActivity` 只 `setWebViewClient`，`window.confirm()` 不弹框、
   直接返回 `false` ⇒ 以 `if (!confirm(...)) return;` 开头的处理函数
   **从来没执行过**。表现是「按钮点了毫无反应」，连报错都没有，最难查。
   现在统一用 `app.js` 里的自绘确认框 `askConfirm()`，网页版和 APK 走同一套。
   ⚠️ 别为了「网页版有原生 confirm」而分两条路：浏览器里测着好好的、
   装到手机上才发现是死的，就是这么来的。
   ⚠️ 点遮罩、按返回键都要把那个 Promise 按「取消」结掉（`askDone(false)`）。
   只把框藏掉的话 Promise 永远悬着，下次点同一个按钮会「第一次没反应」。
9. **「已经登录着」不等于「服务器还认」**（0.1.3 起）。
   带着有效 cookie 去 GET 登录页时，学校服务器会 302 到首页，
   返回的 HTML 里没有 `CryptoJS.SHA1('…-` 那行加盐值 ⇒ 抛「没拿到加盐值」。
   所以 `login()` 开头有一条短路：已登录**同一个学号**就直接复用会话。
   但这条短路的前提没被验证过（服务器那边可能早过期了），
   于是 `doSync()` 失败一次会丢掉会话真登一次再重来，**只重试一次**。
   🔴 拿不到盐值**绝不能**当「已登录」放过去 —— 那是把「没读到」说成
   「登录成功」，随便填个错密码也会绑定成功。
10. **解绑要连教务系统的 cookie 一起丢**。只清本机凭据不清 cookie，
    下次绑另一个账号时服务器还认着旧会话，只能靠上面第 9 条那段补救逻辑绕一圈。

### 两条数据链路的契约是一样的

`app.js` 里所有请求都过 `api(path, body)` 这一个函数：

```js
if (window.NativeApi) return window.NativeApi.handle(path, body);  // APK
// 否则 fetch 到电脑上的 bridge.py                                          // 网页版
```

所以界面只写一份，两个形态行为一致。`native.js` 在没有 `window.Android` 的
环境里会自己 `return`，网页版完全不受影响。

接口一共七个（`bridge.py` 和 `native.js` 都实现）：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | 探活（只有网页版有） |
| GET | `/api/state` | 有没有绑定、绑的哪个学号、凭据状态（`credState`） |
| POST | `/api/login` | `{username, password, remember}` 登录并同步。界面**总是**传 `remember: true` |
| POST | `/api/sync` | 用已存的凭据重新同步（不用再输密码）。凭据没了返回 `needBind`，教务系统不认返回 `authFail` |
| POST | `/api/unbind` | 删掉已存的凭据 |
| POST | `/api/semesters` | 列全部学期（考试页选学期用，界面自己筛成他在读的那几个） |
| POST | `/api/exams` | `{semesterId}` 取指定学期的考试。id 不是纯数字直接回错，不拿当前学期冒充 |

`/api/sync` 的两种失败要分开，因为**该做的事不一样**：
`needBind` → 补密码；`authFail` → 密码可能改过了，也补密码，但话术不同；
其余错误（网络、改版）→ 只提示重试，别弹密码框。

网页版所有 `/api/*` 都要求口令（URL 上的 `?k=` 或请求头 `X-Token`）；
APK 不需要 —— 没有局域网，也没有别人能访问的端口。

### 同一份界面，两套说法

界面只有一份，但「东西存在哪台机器上」这件事两边不一样：
网页版的凭据用 Windows DPAPI 存在**电脑**上，APK 用 Android Keystore 存在**手机**里。
在 APK 里写「存在这台电脑上」就是错的，会让人以为手机在偷偷连电脑。

做法是 HTML 上挂两个属性，`applyEnvTexts()` 按环境挑一个塞回去：

```html
<span data-web="记住账号密码（Windows 加密后存在这台电脑上）"
      data-app="记住账号密码（用手机系统密钥加密保存在本机）">…</span>
```

不用两套 HTML —— 一份界面改一次就够，不会漂。

### 安卓返回键

`window.appBack()` 是三级行为：**先关浮层 → 再回课表 → 最后才退出**。
不加这个的话，课程详情弹着的时候按返回会直接把 App 退掉，下次进来还得重新找那门课。

配色说明：浅色用 **Tailwind CSS 官方色板（MIT）** 的 200/800 两档，
色值是从 `tailwindcss@3.4.17` 的 `colors.js` 里读出来的，不是手抄的
（脚本 `_lab/out/pick_colors4.py`）。深色模式仍用自己推的一套 ——
Tailwind 的 900 档实测发闷、色块糊在一起。

## 打 APK

```bash
cd mobile/android
python build_apk.py            # 出包到 dist/hangyuantong-0.9.0.apk
python build_apk.py --clean    # 先清 build/ 再打
```

不用 Gradle / Android Studio，走官方那套命令行：
`aapt2 compile → aapt2 link → javac → d8 → 加 classes.dex → zipalign → apksigner`。

工具链位置（都在 `_lab/out/sdk/`，不属于本目录）：

| 东西 | 路径 |
| --- | --- |
| JDK 17 | `sdk/zulu17.60.17-ca-jdk17.0.16-win_x64` |
| build-tools 34 | `sdk/android-14`（aapt2 / d8 / zipalign / apksigner） |
| platform-33 | `sdk/android-13/android.jar` |
| 签名密钥 | `_lab/out/keystore/hangyuantong.keystore`（**不在 git 里**） |

几个踩过的坑，改构建脚本前先看：

- `aapt2 link` 的编译产物要当**位置参数**传，用 `-R` 会被当成「覆盖层」，
  每条资源都报 `does not override an existing resource`。
- `d8` **不认目录**输入（`Unsupported source file type`），必须逐个传 `.class`。
- `javac` 在 Windows 上默认按 GBK 读源码，源码里有中文注释就必须加 `-encoding utf-8`。
- XML 注释里不能出现连续两个减号（`--bg` 这种写法会让 aapt2 报
  `xml parser error: not well-formed`）。
- 自适应图标的前景要留安全区：108dp 的画布里只有中间 72dp 保证不被裁。

APK 信息：包名 `com.hobson.hangyuantong`，minSdk 23，targetSdk 33，
`usesCleartextTraffic=true`（教务系统只有 http）。
权限只有三条：`INTERNET`、`ACCESS_NETWORK_STATE`、`REQUEST_INSTALL_PACKAGES`
（最后一条是 0.1.2 加的应用内更新，Android 8+ 还要用户在设置里单独允许一次）。

### 发版顺序（顺序错了会出一个 404 的下载按钮）

```bash
# 1. 改版本号：app.js 的 APP_VERSION/APP_CODE、build_apk.py 的
#    VERSION_NAME/VERSION_CODE、MainActivity 的 UA 后缀、RELEASE-NOTES.md
cd mobile/android && python build_apk.py --clean     # 2. 出包（会重写 version.json）

# 3. 传 CNB（国内线路）—— 必须在发站之前，否则 apk_cn 指向 404
python deploy/upload_cnb.py --artifact hangyuantong --name "航院通.apk" \
       --version 0.1.1 --file mobile/android/dist/hangyuantong-0.1.1.apk

# 4. 生成发布页并发布（工作区根目录）
python make_hyt_site.py && python deploy/deploy.py && python deploy/deploy.py --verify

# 5. GitHub：提交 + 打 tag + Release 带 APK
```

`build_apk.py` 有版本一致性门槛：四处版本号对不上会直接拒绝出包
（`check_version_consistency()`）。这不是麻烦，是防止打出「包里写着 0.1.1、
清单里写着 0.1.0」的包 —— 那种包发出去，检查更新会永远认为「已是最新」。

### 装到手机上

1. 把 `dist/hangyuantong-0.9.0.apk` 传到手机（数据线 / 微信文件传输助手 / 网盘都行）。
2. 点开安装。系统会拦「未知来源」——在弹窗里选「仍要安装」或去设置里
   给这个文件管理器/浏览器开「安装未知应用」。
3. 打开就能用。教务系统 `jwglxt.zua.edu.cn` **在校外也能连**（不用挂 VPN），
   手机流量、家里 WiFi 都行。
4. 进「我的」→ 填学号密码 → 绑定并同步，等 12~15 秒。

> 签名是自签的（`CN=HangYuanTong`），不是应用商店的证书，所以每次覆盖安装
> 都必须用同一把 keystore（`_lab/out/keystore/hangyuantong.keystore`）。
> 这把钥匙丢了，以后就只能卸载重装，用户数据全没。

### 打包前会挡一道版本一致性

版本号散落在几个地方，改一处漏三处是迟早的事，所以 `build_apk.py` 一开头
就会核对：**`web/app.js` 的 `APP_VERSION` / `APP_CODE`**（唯一来源，界面自己
也读它）、`build_apk.py` 的 `VERSION_NAME` / `VERSION_CODE`、`MainActivity`
的 User-Agent 后缀、`version.json` 的 `version` / `code`、`strings.xml` 的
`app_name`。对不上直接退出，不让出一个版本号自相矛盾的包。

### 打完包会顺手更新 version.json

`size` 和 `sha256` 只能从真实的包算出来，手填迟早会出现「清单里的 sha256
和下载到的文件对不上」。所以打包最后一步会把这两个字段、以及下载地址
一起写回 `mobile/version.json`；`notes`（更新内容）从 `RELEASE-NOTES.md`
里**本版本那一节**抄。

发版时因此只要动三个地方：`app.js` 的版本号 → `build_apk.py` 的
`VERSION_NAME`/`VERSION_CODE` → `RELEASE-NOTES.md` 加一节。跑一次打包，
清单自己就对了。

### 发布页

`site/index.html` 是下载页的模板，里面七个占位符
（`{{BRAND}}` / `{{VERSION}}` / `{{SIZE}}` / `{{DATE_TAIL}}` / `{{NOTES}}` /
`{{CNB_BTN}}` / `{{CNB_NOTE}}`）由 `../make_hyt_site.py` 用 `version.json`
里的值填掉，再把 `version.json` 和 APK 一起放上去。

⚠️ 是 `{{DATE_TAIL}}` 不是 `{{DATE}}`：它自带前导的「 · 」，
因为没打过 tag 的版本没有日期，`{{DATE}}` 留空会在页面上剩一个孤零零的分隔点。
`{{CNB_BTN}}` / `{{CNB_NOTE}}` 也一样，是**整块**而不是地址 ——
清单里没有 `apk_cn` 时整块不出现，不能留一个空的 `href=""` 按钮。
发布脚本会检查有没有没替换掉的占位符，有就报错退出。

`{{CNB_BTN}}` / `{{CNB_NOTE}}` 是**整块**占位符，不是 `href="{{CNB_URL}}"`：
清单里没有 `apk_cn` 时整块不出现。写成一个空 `href` 的按钮的话，
点下去会回到本页，用户以为在下载；而且「两个按钮下的是同一个包」
那句话在只有一条线路时也不成立。**宁可少一个按钮，也不能说一句当前不成立的话。**

页面是**单文件、零外部请求**（CSS 全内联，图片只用同源的图标），
这样把 `index.html` 单独拷走也能打开看。⚠️ 站点 CSP 是
`default-src 'self'`，别在里面引 CDN 的字体或图片 —— 会被静默拦掉。

> 发布脚本（往 Cloudflare Worker 传文件、写 `_headers`）在维护者的
> 构建工作区里，不在本仓库。想自己搭一个的话，把这四个文件放到任意静态托管上
> 就行：`index.html`、`version.json`、`dl/*.apk`、图标。

## 隐私

这个 App 会碰到学号、密码、课表、成绩、考试安排，所以有几条硬规矩：

**1. 源码里不许出现真实身份信息**

2026-10-18 踩过一次：绑定页的学号输入框占位符写成了「例如 + 真实学号」——
那串数字会**原样打进 APK**，而且就摆在「首次登录」最显眼的位置。
解压 apk 谁都能看到。现在改成 `例如 2023123456`（明显是假号）。

回归用例 `_lab/out/check_privacy.py`：扫源码 + 逐个解开 APK 条目扫（含 `classes.dex`
这种二进制），检测词从 `repo/local_secrets.py` 动态读 —— **检测脚本自己不能存真值**，
否则它就成了新的泄露源。现在 11 项：

```bash
python check_privacy.py --live   # --live 会真起一次服务，验日志打码
```

⚠️ `--live` 起服务用的是 `mobile` 那个 venv（里面有 `requests`），
不是跑脚本自己的解释器。用错解释器的话服务直接 import 失败，
症状是「日志里没找到 GET 行」，**看着像日志没打码，其实是服务没起来** ——
所以脚本现在会先把 traceback 打出来，并且明确说「这一组结论无效」。

**2. 日志里不许出现访问口令**

网页版的地址是 `http://<电脑IP>:8788/?k=<token>`，那个 token 就是唯一凭证。
`bridge.py` 的终端日志原来会把整条 URL 打出来，截个图、投个屏就漏了。
现在 `log_message()` 里用正则把 `k=` 后面打码成 `k=***`。
（启动横幅里那一次完整 token 是**故意**的 —— 那是给用户抄的，不算日志。）

**3. 凭据只加密落盘**

| 形态 | 存哪 | 怎么加密 |
| --- | --- | --- |
| 网页版 | 电脑 | Windows DPAPI（`account.bin`） |
| APK | 手机 | Android Keystore，AES-256-GCM（`SharedPreferences` 里只有密文） |

两边都是「密钥由系统保管，文件里只有密文」，把文件拷走解不开。
局限要说清楚：root 过的机器、能在 App 进程里跑代码的攻击者照样能解 ——
它不是「绝对安全」，只是「拷走文件没用」。

**存不存是用户说了算吗？** 现在是**一律存**，没有勾选框。
原因不是图省事，是那个勾选框会造出「数据在、密码没存」的半绑定状态
（见上面「登录状态和密码记忆」）。想不存就点「解除绑定」，那会把凭据删干净。
代价是：别人拿到你解锁的手机，能直接看到课表成绩 —— 这和「手机里存了
一个自动登录的 App」是同一类风险，自己权衡。

**4. APK 侧的加固**

- `allowBackup="false"` —— 挡住 `adb backup` 把数据导出
- `setAllowFileAccess(false)` / `setAllowContentAccess(false)` ——
  页面全在 assets 里，用不着读手机文件，关掉少一条被注入后读本地文件的路
- `shouldOverrideUrlLoading` 只放行 `app.local` —— 页面不该跳到外面去
- `setSaveFormData(false)` —— 不让 WebView 自己存表单/密码（凭据走 Keystore）
- 学号在界面上打码显示（`2023****56`），防「路过看一眼」和截图外传

**5. 不发出去任何东西**

不连第三方服务器、不统计、不上报。只访问两个地方：
学校教务系统（`jwglxt.zua.edu.cn`）和你自己电脑上的 `bridge.py`。

> ⚠️ 有一处要自己留意：网页版的 `?k=<token>` 会进浏览器历史记录。
> 共用电脑的话，用完可以「清除本机缓存」或换一个 token（删掉
> `%LOCALAPPDATA%\DaXiaoZhu\token.txt` 重启服务会重新生成）。

## 引用了哪些外部项目（许可与署名）

用户 2026-10-31 问：「咱们项目引用了 zuawiki 和出水小部件这两个项目，
需不需要向作者请示？」查了代码，结论是**两个都不需要事前许可**，
但理由不一样，记在这里免得下次再查一遍。

| 项目 | 作者 / 许可 | 我们用了什么 | 我们**没有**用什么 |
|---|---|---|---|
| ZUA Wiki（`wiki.zua.fan`） | 在校学生自建，未开源（站上写「预计近期上线 GitHub」） | 13 条「标题 + 相对路径」，点了在系统浏览器打开原站那一页 | 没有正文、没有图片、没有搬运、没有镜像 |
| WaterWidget（`nocookies111/life-798`） | MIT License | 包名字符串 `com.water.widget`，用来判断「装没装」和 Intent 拉起 | 没有它的源码、没有它的密钥、没有它的二进制 |

**ZUA Wiki：只做入口，不复制正文**

- 站上写着「任何复制、转载请注明出处！严禁用于商业用途！」
- 我们的做法恰好满足这两条：界面里明写「在校学生自己写的，不是学校官方，
  也不是我们做的」，还摆着 `wiki.zua.fan` 域名和「打开原站首页」按钮 ——
  这就是「转载请注明出处」；航院通完全免费（无收费、无赞助、无广告）——
  就不构成「商业用途」
- 抄的只有 13 个页面标题。标题通常是短语，不构成受著作权保护的作品；
  而且已注明来源
- `WIKI_HOME` 是唯一的域名出口，`check_wiki_links.py`（36 项）盯着
  「必须是相对路径」+「拼出来必须还在 `wiki.zua.fan` 里」，
  防的正是「哪天有人往里塞绝对地址把流量导去别的站」

> 虽然不必请示，**打个招呼仍然值得**：一是我们是免费帮它导流，一般乐见；
> 二是那 13 条路径是手抄的，对方改站点结构我们就会 404，
> 打个招呼能顺带问到变更通知。成本为零，收益是「不会突然全红」。

**WaterWidget：MIT 许可，连代码都没复制**

- MIT 本身就允许「使用、复制、修改、合并、发布、分发、再许可、销售」，
  **不需要事前征得同意**，唯一的形式义务是「保留版权声明和许可声明」——
  而这义务的前提是**分发对方的软件**。我们从没分发过它的代码或二进制
- 实际做到的比要求更干净：仓库里没有 WaterWidget 源码
  （`_lab/out/_l798b/` 那份反编译目录被 `.gitignore` 排除，只在实验里看过），
  APK 里 `grep -i water` 结果为 0
- 只用了 `com.water.widget` 这一个**包名字符串**去做「是否安装」检测和
  `getLaunchIntentForPackage` 拉起 —— 这是 Android 的公开互操作机制，
  相当于「知道对方的门牌号」，不涉及对方任何代码
- 我们**也拿不到**对方的密钥：网关地址和签名盐值在对方的
  `secrets.properties` 里，不公开。所以谈不上「借用接口」，只能拉起
  用户自己已经登录好的那个 App
- 界面上已经写全了（`index.html` 关于页）：
  「照着 **WaterWidget**（nocookies111/life-798，MIT 许可）公开的接口协议
  自己实现的，与该项目的开发者无关，也不代表慧生活798 官方」——
  项目名、作者、许可证三样都点了名，比 MIT 要求的形式义务更周到

> 将来如果真要**复制**它的代码（而不是照协议自己写），那时才需要
> 把它的完整版权行和 MIT 正文放进一个 `NOTICE` 文件。现在不需要。

## 已知限制

- **教务系统校外也能连**（实测手机流量、家里 WiFi 都能登录），不用挂 VPN。
  连不上的时候先看网络：校网认证过期、或者学校那边临时维护，都会表现成同步失败，
  但已经存下来的课表还能看。
- **同步大约 12~15 秒**。要登录一次、再依次抓学籍/课表/成绩/考试，
  中间刻意留了 1.2 秒间隔（打太快会被判「点击过快」直接拒绝）。
- **当前学期（2026-2027-1）的考试安排是空的**：接口已经打通
  （`semester.id=297`、批次「平时结课考试」），表头字段也齐全，
  但**学校还没发布排考**，tbody 是空行。
  界面会照实说「学校还没发布考试安排」，而不是说「没有考试」。
  等学校排好考，同步一次就有了。
  **往前的学期有数据**（实测 2025-2026-1 有 7 条、2025-2026-2 有 11 条），
  在考试页顶部切学期就能看到。
- **不能后台自动同步**。App 关掉就停了，做不到「每天自动更新」。
- **空闲教室的结果是「这一刻」的**：学校只按「第几节」算，不按分钟。
  同一天同一节，上午查和下午查是同一个答案；但它不会自动刷新 ——
  看的是你最后一次点「查询」时的结果，界面上写着日期和节次。
- **空教室一次能回七百多间**，全都画在一页里。想找某一间就用「筛选 → 教室名」
  输半截名字（比如 `01B`）；靠滚是不现实的。
- **APK 没有在真机上跑过**（开发机没有安卓设备/模拟器）。
  已验证的是：解析结果和 Python 版逐字段一致、数据层对着真实教务系统跑通、
  APK 签名和结构完整。装到手机上第一件事请先试「绑定并同步」。
- **检查更新依赖发布站**（`hobson2233.dpdns.org`）。站被墙、或者哪天没续域名，
  就查不到新版本 —— 但这只是「不知道有新版本」，其他功能一点不受影响。
  GitHub 那份清单是备用源，国内基本连不上，别指望它。
- **更新是「下载新 APK 让你自己装」，不是应用内静默升级**。
  自签名包走不了商店，装的时候系统会拦「未知来源」，得手动同意。
